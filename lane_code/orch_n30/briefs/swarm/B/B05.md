## Goal and why this task matters
We are training a ~9B spatial VLM, end to end from RGB, whose chain of thought calls heads inside its own checkpoint and answers from what they print; it must beat open 9B models on ReVSI, VSTI and VSI-Bench and later serve as a cheaper base for navigation fine-tuning. A training leg is one 24-hour Orchard job on 4 H100 that spends about 3.5 h before its first step and then reaches only about 450 steps at about 133 s a step, and the reads that judge each boundary take 4 to 6 h on one GPU slot, so every minute removed buys more steps or more experiments. Mode p's pointing (~38.6 min) and routing (~23.9 min) substages run on CPU while 4 H100 wait, and the same geometry code runs inside tower calls during reads; Python loops over pixels, boxes or frames there cost GPU-hours indirectly.

## Question
Which geometry functions run inside mode p (pointing and routing) and inside the read path, where do they spend their time, and how much faster can they run with outputs exactly equal?

## Method
1. Map callers: which of these functions mode p's pointing and routing substages and the tower read path call (carrier_c1_run.prepare 465 and the modules it imports; tower_read.py, g3t_online.py). Record the call graph in files/B05/CALLERS.md.
2. Make synthetic inputs at the real shapes (32-64 frames, the depth and mask resolutions the code expects, tens to hundreds of boxes or instances per scene) and profile each hot function with cProfile and timeit.
3. Rewrite the top functions with numpy broadcasting, bincount or searchsorted, or scipy where the env has it, keeping dtype and accumulation order so outputs are bitwise equal; where exact equality is impossible, state the tolerance and why it cannot change a decision downstream.
4. Tests: old versus new on 50 random seeds plus the existing fixtures, bitwise equal or within the stated tolerance; run the existing tests for the files you change (targeted, not whole suites).

## What counts as a finding, and its price
A finding is a function with its file:line, its share of a substage or of a read item, the speedup measured on CPU, and an equality test. Price as minutes per leg (mode p share x speedup) times 4 H100, and as seconds per read item.

## Out of scope
Changing geometry semantics, thresholds or the tower models; GPU kernels (note them as follow-ups only).
