## Method
1. Copy the tree and the kit into S/work/H01/tree and S/work/H01/kit; edit only those copies; deliver every change as `diff -ruN` against the staged originals.
2. Stand-in: a model with the production class structure and tiny dimensions (untied), tiny rows (at least one per stream the loader needs) and tiny frames. Name every seam in R/files/H01/SEAMS.md: file:line, what production does there, what the rehearsal does, and which check the seam skips.
3. One command, `bash S/work/H01/rehearse.sh [--case NAME]`, that runs job.sh's real path with the scheduler simulated: the environment Slurm sets (SLURM_JOB_ID, SLURM_TMPDIR, node-local log paths), `--export=NONE` behaviour, TK_JOB_START, and a compressed clock so that stop_before and wall fire within minutes. Inject the compression through the path production reads (environment or config); if the sealed constants can only be changed by editing sealed bytes, that is a finding.
4. Happy path, each check an assertion with its evidence file: preparation receipt; step-1 checkpoint; an ordinary timed checkpoint; an export at a milestone (move the milestone list to steps 2-3 through the config path); the stop signal (SIGTERM to the batch shell, as Slurm's B:TERM@600 sends) and the self-stop; the final pass in the order the card states (stop checkpoint, stop export, logs, exit archive, upload log u, then ordinary checkpoints newest first, inside the 150 s reserve rule); then the resume: a second job from the stop checkpoint with resume_pin latest that continues the global step count (step s+1, never 1), restores optimizer state, LR-schedule position, sampler position and RNG, and names its next export by the right step. Compare the losses of steps after resume with an uninterrupted run of the same steps; state whether they match exactly or within a stated FSDP tolerance, and why.
5. Strict sink: a local HTTP server implementing the resumable-upload protocol the copier uses, as strictly as Google Cloud Storage: create-only sessions (112 per job, names from k/y.json), PUT with `Content-Range: bytes a-b/total` and status queries with `bytes */total`, 308 with `Range: bytes=0-n` while incomplete, 200 or 201 on the final byte, chunk sizes that are multiples of 256 KiB except the last, and refusal of gaps, overlaps, malformed or out-of-order ranges, size changes and unknown or expired sessions (404 or 410); checksum headers if the copier sends them. Read the copier first so the sink speaks its exact protocol. Redirect the copier by its endpoint configuration only; never replace or subclass a stdlib class (that is the defect that sent no byte on 2026-11-20). Write each rule you enforce with its documentation source in R/files/H01/SINK_RULES.md, and test the sink itself with planted malformed requests (pytest).
6. Failure cases, each runnable alone with `--case`: (a) project folder full (inject ENOSPC at the filesystem seam for paths under the project folder X only, in the child processes; name the seam); (b) upload sessions missing, incomplete or malformed; (c) upload interrupted (connection dropped mid-part, a 5xx, a stall beyond the copier's timeout), then resumed through a status query; (d) a worker import missing in a child process (for example scipy absent from a child's sys.path); (e) environment dropped by `--export=NONE` (start the job under `env -i` plus only what Slurm sets, and check every child for PATH, HOME, PYTHONPATH, TMPDIR and cache directories); (f) a stop signal during a checkpoint write; (g) a second TERM; (h) node-local disk nearly full at the stop checkpoint. Each case asserts the expected named refusal or recovery, and that the exit publishes its cause.
7. Report every defect the rehearsal exposes in the tree and kit as they stand: reproduction command (`bash rehearse.sh --case X`), file:line, expected against actual, and a price (GPU-hours lost if it fired in N's leg; for example, a broken resume costs the second job's preparation, about 9.6 H100-hours, plus the lost steps).

Order of work: the resume rehearsal and its defects come first; then the strict sink with the copier's final pass; then the failure cases. If time runs short, deliver what you have in that order.

## What counts as a finding

CONFIRMED needs the case's reproduction; a defect seen only by reading is SUSPECTED.
