# F07: evaluation harness skeleton for continuous-environment navigation (VLN-CE, R2R-CE) with a stub simulator and tests

Read /data2/jjyeung/agent_project_data/distillation_orchestrator_20260918/orch_n30/briefs/swarm/SWARM_RULES.md first. It binds you, and so does the file it names first.

## Goal and why
The project builds a ~9B spatial VLM that answers from RGB and calls heads inside its own checkpoint in its chain of thought; its second goal is to be a cheaper, better base for navigation fine-tuning, where VLN-CE and R2R-CE matter most to the user. A full runner (`navrun`, habitat-sim 0.2.4) was built on 2026-11-11, but its only copy sits on trinity-2-18, which is unreachable. Rebuild its harness layer now, with a stub simulator behind a clean interface, so that plugging in habitat-sim later is a small adapter and the metrics are already proven.

## Inputs (read-only)
- The spec: /data2/jjyeung/agent_project_data/distill_design/VLA_NAV_RUNNER_20261111.md (8 KB; read once). Key conventions: forward 0.25 m, turn 15 degrees, stop, a 500-step cap, a 3 m success radius, sliding on; RGB 512x512, HFOV 90, camera at 1.25 m; one policy interface `act(history_frames, instruction, state)` with output formats text, nav, waypoint, click, chunk; history of 32 frames at decision state t = states `[i*t//31 for i in range(32)]`; metrics NE, SR, SPL, OSR, TL, nDTW (fastdtw, as in VLN-CE) and SDTW; lists keyed by seed with an ordered-id sha256; train scenes must never be val-unseen or test scenes.
- No other inputs. Do not download habitat, datasets or scenes.

## Build (Python 3.12, standard library plus numpy; use /scratch/jjyeung/envs/p1cpu/bin/python; install nothing; if fastdtw is absent, implement exact DTW in numpy and say so)
Work only in /scratch/jjyeung/swarm_20261120/work/F07 (create package work/F07/navharness/ and tests work/F07/tests/).
1. `sim.py`: a `Simulator` protocol (reset(episode) -> obs, step(action) -> obs, agent_state(), geodesic_distance(a, b), is_navigable(p)) and `GridStubSim`, a deterministic 2D occupancy-grid simulator with sliding along walls, used only for tests. A `HabitatSim` adapter class whose methods raise NotImplementedError with a message naming habitat-sim 0.2.4 and the config keys it will need.
2. `episodes.py`: R2R-CE episode schema (episode_id, scene_id, start position and rotation, goal position, reference path, instruction), a loader for the VLN-CE json.gz layout, a scene-split audit that refuses overlap between train and val-unseen or test, and list building with seed and ordered-id sha256 as the spec describes.
3. `policy.py`: the `act` interface and decoders for the five output formats; strict parsing, with a parse failure counted and mapped to `stop` or a refusal by config, never silently to forward.
4. `history.py`: the 32-frame history rule above, configurable length, unit-tested at t = 0, 1, 31, 32, 500.
5. `metrics.py`: NE, SR, SPL, OSR, TL, nDTW, SDTW with the VLN-CE definitions (success at NE <= 3 m after stop; SPL uses geodesic shortest-path length; nDTW = exp(-DTW / (|R| x 3 m))); per-episode records and a summary with bootstrap intervals over episodes (seed 20261120).
6. `run.py`: the closed loop (reset, act, step, until stop or the 500-step cap), resumable per episode (one JSON line per finished episode; a restart skips finished ids), and a summary file.
7. Tests: metrics on hand-computed paths (a perfect path gives SR 1, SPL 1, nDTW 1; a stop 3.01 m away fails; an oracle that takes the long way has SPL equal to shortest over taken); a shortest-path oracle on GridStubSim reaching SR 1.0 on 50 generated episodes; random and forward-only baselines; sliding; the step cap; the parse-failure rule; resume after a simulated crash; the scene-split refusal; the history rule.
