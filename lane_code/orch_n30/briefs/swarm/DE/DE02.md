## The grammar (trace ruling of 2026-11-15, sections 2.1 to 2.3, amended 2026-11-16; adopted)
A trace has four kinds of line: Locate (an object and one frame where it is seen, optionally a coarse image region), Relate (a relation in words), Step (the question's own logic: restating its clause, a half turn, listing instances, a sum), and Call (program types only; none belongs in this store). Numbers allowed: frame indices, counts of listed items, results of explicit arithmetic on those, and constants the question states. A length, area, angle or coordinate never appears; for a numeric type the estimate appears only as the answer after `</think>`. Frames are cited one per object, never as an exhaustive list and never as "absent in". No trace is empty. Facing pairs: the away row words the forward relation as a condition, then the half turn, then the turned relation; medium uses three bands, and under a half turn "ahead, slightly to one side" becomes back, "out to one side" becomes the other side, "behind, on one side" becomes the other side.

## Question
Per pool and question type, how many rows per 1,000 break the grammar, and how many rows' answers disagree with what their own trace states?

## Method
1. Check the store; count rows by pool × type and compare with the list above.
2. Write trace_grammar.py and run it over every row:
   - G1 empty or whitespace think (answer-only).
   - G2 procedure-only: no object-specific fact (no frame index, no relation word, no instance list, no ordered list), as in the r1g counting example.
   - G3 stated measurement: a number in the think text that is not a frame index, a count of listed items, an explicit sum of listed counts or a constant the question states; any number with a length, area or angle unit; any decimal.
   - G4 a call tag (`<ground`, `<gap`, `<move`, `<turn`) or `<tool_response>` in a trace.
   - G5 Locate form: an object the family's form locates but the trace names without a frame (direction triples, relative-distance anchor and candidates, appearance-order objects, counting instances); frame index outside 1..32; several frames for one object in one Locate line; "absent"; region words outside a small vocabulary you state.
   - G6 answer follows trace, per family: relative distance (first of the nearest-to-farthest list, or last for farthest, is the answer option's text); appearance order (the listed order is the answer option's sequence and the listed frames ascend in it); counting (listed instances = stated count = answer); totals (each list's length, the sum's arithmetic, the answer); first-seen frame (stated frame = answer); direction (the concluding relation maps to the answer option; for away rows the conclusion is the half turn of the stated forward relation); route planning (the trace's turn list is the answer option's); VSTI relations (stated relation = option); camera-object distance (first of the ordered list = answer); box_3d (JSON in the trace = answer); room and object size (no number in the think text).
   - G7 facing twins: for each pair_id with a toward row and an away row, the away row's forward relation equals the toward row's relation, and the away answer is its half turn.
   - G8 cross-row consistency within a scene: two rows that call different frames the first-seen frame of the same normalized object name; a best-view ("Seen") frame earlier than that object's first-seen frame in another row. Count conflicting (scene, object) pairs and the rows involved, by pool pair.
   - G9, if time allows: placeholder object names ("remove", "split", "object", "otherfurniture", "unknown"); text after the answer; answer format (letter or option text).
3. Check your classifier by hand: read 5 rows per pool × type stratum (random.Random(20261120).sample over the stratum's sorted i), mark G1 to G6 yourself, and report agreement; fix the classifier until agreement is at least 95%.
4. Rates per 1,000 rows by pool × type with Wilson 95% intervals; files/DE02/defects.csv.gz with i, qid, pool, type, class and a 120-character excerpt; three examples per class in the result.
5. files/DE02/test_grammar.py: each check on hand-made good and bad rows plus real failing rows. Run it and keep its output.
