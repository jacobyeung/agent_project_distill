## Question
In how many rows, per source and type, does the final answer disagree with the row's printed values, its own arithmetic, the unit or option the question asks for, or a separate source label; and how many rows break the program form?

## Method
1. Inventory: list tables, columns, indexes and row counts; decode one row per type in full into files/DE01/schema.md. Name the fields that hold the question, options, trace or events, final answer, source group, scene, any ground-truth label and any admission flag. Count rows by source and type and compare with the expected counts.
2. Rebuild each row's trace as the model sees it and parse every call and response: move (dx, dy, dz, distance), turn, ground box (frames, best frame, centre, size, yaw), gap (distance) and any failure status.
3. Check every row, not a sample:
   - A1 camera_displacement: printed distance against sqrt(dx²+dy²+dz²), tolerance 0.02 m; the stated value and the final answer equal the printed distance; the call's frames equal the question's frames.
   - A2 camera_movement_direction: recompute each option's component from dx and dz with the trace's mapping; the largest names the option; that option's letter in the options list is the final answer. Report near-ties (top two within 0.05 m) separately as label-noise risks, not as errors.
   - A3 camera_rotation: final answer equals the printed turn and lies in (-180, 180]; the stated sign convention agrees with the question's.
   - A4 absolute_distance and units: the final answer equals the printed gap converted to the unit the question asks (m, cm, mm, ft, in, yd; factors 1, 100, 1000, 3.28084, 39.3701, 1.09361) at the precision the trace states; every conversion line's arithmetic holds to its shown decimals; any unit mismatch between question and answer is a defect.
   - A5 source label: if a row carries a ground-truth value or option separate from its printed responses, compare the final answer with it (exact for letters, ratio for numbers). Count rows beyond 15% (the trust tolerance of the 2026-11-15 trace ruling) and beyond 50%; histogram answer/label by dataset. A mode near 1.16 on ScanNet++ rows is the known half-extent defect.
   - A6 form: answer format per type (`<answer>…</answer>` or bare value) and rows that differ from their type's majority; empty think; refusal endings; failure-status rows (count them; a direct answer must follow and no call may repeat); call kinds that do not belong to the type; room rows in program form; any number outside the allowed set (whitelist a template constant only when it appears verbatim in call text, such as "5 cm" from rule="box_grid_5cm", and list each one you whitelist); response text inside a supervised span when the row records loss masks or event spans.
4. Count defects per 1,000 rows by source × type with Wilson 95% intervals. Keep every defective row's i, qid, class and the numbers involved in files/DE01/defects.csv.gz (under 5 MB).
5. Write files/DE01/test_checks.py: each checker on hand-made good and bad rows, plus five real defective rows (text only) copied from the database. Run it and keep its output.
