## Goal and why this task matters
We train a ~9B spatial VLM whose chain of thought calls heads inside its own checkpoint and answers from what they print; it must beat open 9B models on ReVSI, VSTI and VSI-Bench. ## Question
How many rows repeat a fact another row already teaches (and how many of those disagree on the answer), and does any row come from a development question, scene, room or video?

## Method
1. Inventory only the fields you need: i, qid and any source qid, type, source group, dataset, scene, room or venue, question, options, frames used (indices, timestamps, total_num_frames, fps), printed responses, final answer. Write files/DE03/fields.md.
2. Exact duplicates: identical target text; identical (scene, normalized question, options, answer). Count groups and extra copies by source × type.
3. Near-duplicates. Distance rows: same scene + same unordered object pair (lower-cased, articles dropped, a singular rule you state) + same unit; split same frame sample from different frame samples. A pair asked in metres and again in another unit is a designed units twin: report twins separately, not as defects. Camera rows: same scene + same (from, to) frames + type; the reversed frame pair as a related class. Cross-source: the same (scene, object pair) in two or more of ARKIT_gen_r2, T0_gen_r2, T1H1_gen_r2, T1H2_gen_r2 and U_Faithful, tabulated by source pair. For every near-duplicate group, test whether the answers (after unit conversion) agree within 5%; disagreeing groups are conflicting supervision and rank first.
4. Concentration: rows per scene and per room; the share of rows from the top 1% and top 10% of scenes; scenes above 100 rows.
5. Development overlap:
   a. Question ids: normalize development ids (strip devrows:, backdir_, forwardtwin_ and room_) and match them against every id-like field of every row, including ids embedded in longer qids (for example a0_room_vsi590k_058996 holds vsi590k_058996). A match means the same source question sits in the database.
   b. Scene and room names: normalize both sides to dataset family + native id (ScanNet sceneNNNN_00 and sceneNNNN_01 are one room; ScanNet++ scannetpp and scannetppv2 ids compare equal; ARKit captures compare by capture, and by venue where a row carries one); opaque ids compare only verbatim. Report how many development scenes and rooms could not be compared because of id form.
   c. Video fingerprints, where rows carry them: equal (dataset family, total_num_frames, fps, width, height) on both sides is a candidate same video; equal or overlapping frame index sets confirm it. Report candidates and confirmed matches separately.
   Report matches per development set (dev-S1, R0-dev, facing twins, held-out camera, room-134; CORPUS_MAP.md's table gives each read's set) with row i, qid and the development item ids.
6. Keep files/DE03/dups.csv.gz and files/DE03/overlap.csv, and one script that reproduces every count; run it twice and confirm the outputs are identical.
