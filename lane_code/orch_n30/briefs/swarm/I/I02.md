## Question
For each dataset and each adapter: which units, axis order, up axis and handedness; which box parameterization (full or half extents; center, corner or min-max; axis-aligned or oriented, and the rotation convention); which instance identifiers (stable across frames, 0- or 1-based, background id); which camera convention (camera-to-world or world-to-camera, OpenCV or OpenGL axes) and intrinsics; which depth units; which frame timing (frame index or timestamp, fps, 0- or 1-based, which frame a question cites)? Where do two adapters, or an adapter and its consumer, disagree?

## Method
1. Convention table (R/files/I02/CONVENTIONS.md): one row per dataset and adapter, one column per convention; each cell carries its evidence (file:line) and a mark CODE (read in code), TEST (asserted by an existing test) or DOC (from a record or the dataset's documentation). Flag every cell where two places disagree.
2. Synthetic scene generator: objects as oriented boxes with known full extents, centroids and yaw; a known camera trajectory, intrinsics and depth; written in each dataset's native on-disk format as the adapter reads it (ScanNet aggregation and segments with the axis-alignment matrix; ScanNet++ v1 and v2 annotation formats; ARKitScenes annotation boxes; ADT where an adapter exists).
3. Property tests (pytest, R/files/I02/tests/): recovered extents equal the truth (catches half against full); centroid distances and closest-surface distances equal the truth (catches axis swaps and unit errors); recovered axes have determinant +1 (handedness); a known 3D point projects to the expected pixel through the adapter's pose and intrinsics (catches camera-to-world against world-to-camera and OpenGL against OpenCV flips); frame index and timestamp round-trip; instance ids stay stable across frames; room footprint and area match. Metamorphic tests: rotating the whole scene about the up axis leaves every distance unchanged; a millimetre input is detected or converted.
4. Run every test against every adapter and every consumer that re-reads boxes or extents. Hunt the siblings of the ScanNet++ v1 half-extent defect: other paths that read the same box or raster store (size labels, room size, extent receipts, lifting boxes, grounding targets), ScanNet++ v2, ARKitScenes boxes, and any code that compensates by 2x twice or not at all.
5. For each failure: the failing invariant, file:line, the defect class, and a price from record counts (for example, 3,362 of N's 11,663 distance rows come from ScanNet++ v1 scenes and the corrected-to-stored median was 0.86) or "unpriced" with the reason. Fixes are diffs against the staged files, behind a flag that defaults OFF.

## What counts as a finding
An adapter or consumer whose output breaks a property on a synthetic scene in its own native format, or two code paths that assume different conventions for the same data. CONFIRMED needs the failing test; a disagreement seen only by reading is SUSPECTED.

## Out of scope
