## Goal and why this task matters
We train a ~9B spatial VLM whose chain of thought calls heads inside its own checkpoint and answers from what they print; it must beat open 9B models on ReVSI, VSTI and VSI-Bench. Every training label for distance, size, count and pose comes from these adapters. On 2026-11-17 we found that ScanNet++ v1 assets store half box extents without declaring it, which inflated ground-truth distances by about 1/0.86 in thousands of training rows. This task looks for the next defect of that kind before the next training boundary.

## Question
Per dataset (ScanNet, ScanNet++ v1, ScanNet++ v2, ARKitScenes), does each adapter produce boxes, distances, sizes, counts and camera poses in one stated convention? Check:
1. Box extents: full versus half extents, read from each source format; whether the declaration flag is honoured everywhere a box is built; oriented versus axis-aligned boxes; yaw applied to extents.
2. Axes and up direction: Z-up versus Y-up per dataset, the axis alignment matrix of ScanNet (axisAlignment in the scene meta file) applied once and to both meshes and poses, ARKitScenes' gravity alignment.
3. Units: millimetre depth (ScanNet .sens, ARKitScenes) versus metres; feet conversion in question text.
4. Instance joins: segment-to-instance-to-label joins, label maps (raw category to NYU40 or to benchmark names), instances split across segments, duplicate instance ids, objects that cross the room boundary.
5. Counting: which instances count (minimum size, visibility), and whether the room filter and the count use the same instance set.
6. Room geometry (room_* modules): floor polygon from which source, area units, wall height.

## Method
Read each adapter, then write CPU tests on synthetic fixtures in each source format (a tiny scene with two known boxes, a known axis-alignment matrix and a known pose) and call the real loaders. Compare the same synthetic object passed through two adapters: they must give the same distance and size. Use /scratch/jjyeung/envs/p1cpu/bin/python with CUDA_VISIBLE_DEVICES= OMP_NUM_THREADS=4 and `nice -n 10`. For shapely, `pip install --target /scratch/jjyeung/swarm_20261120/work/A06/pylib shapely` and add it to PYTHONPATH; never install into a shared env. Real dataset files are not staged; do not fetch them.

## What counts as a finding, and its price
A wrong box, distance, size, count or pose on a synthetic input, shown by a test, with the dataset and the question types it reaches. Price it by the share of training or development items from that dataset and type (the development corpus at /scratch/jjyeung/swarm_20261120/corpus/673bc60f_s200_devS1R0_direct_a8102c3207b.jsonl gives scene prefixes and question types per item; read it as a stream) and the MRA change the error causes; otherwise "unpriced" with the reason. Re-finding the known ScanNet++ v1 half-extent defect is not a finding; finding a path that the fix (declared-convention doubling) misses is.
