## Question
Does the scorer give every recorded response the score the official rules give it? Check:
1. Answer extraction (answers.parse_answer): `<answer>` tags, several answers in one response, answers inside the trace versus after it, trailing units ("4.66 ft", "350 cm"), commas, negative numbers, scientific notation, words for numbers, empty answers, a response cut at the token cap.
2. Option mapping: letter versus option text, options written "A. sofa" versus "sofa", duplicate option texts, case and punctuation.
3. Mean relative accuracy: thresholds 0.50 to 0.95 in steps of 0.05, the direction of the relative error, a truth of zero, unit conversion between the question's unit and the truth's unit, the truth stored as a string.
4. Which level or field the scorer reads (answer versus response_text versus trace), and whether routed responses whose answer is printed by a head are scored on the right span.
5. Aggregation: per-type mean then type mean, versus item mean; how unscored or parse-failed items enter the denominator.

## Method
1. Write a re-scorer script that streams every corpus file, re-extracts each arm's answer from response_text with the harness's own functions, re-scores it against truth.scored with the scorer named in truth.scorer, and compares with the recorded answer and score. Write a disagreement table: read_id, item_id, question_type, arm, recorded answer and score, re-scored answer and score.
2. For every class of disagreement, find the code line responsible and write a unit test that shows it.
3. Add tests for the edge cases in the list above that the corpus does not cover.
Use /scratch/jjyeung/envs/pdtest_v1/bin/python (has torchvision) with CUDA_VISIBLE_DEVICES= for tests that import frames.py; /scratch/jjyeung/envs/p1cpu/bin/python otherwise; OMP_NUM_THREADS=4, `nice -n 10`.

## What counts as a finding, and its price
A response scored differently from the official rule, shown by a test, with the count of affected items per read. Price it as the change in the read's mean (points) on the affected reads, for example dev-S1+R0-dev direct (3,120 items) or dev-S1 routed (636 items). A disagreement between the recorded score and HEAD's code that the sealed code explains is a version difference, not a bug; report it separately.
