## Question
Which experiments, run after vehicle N, most raise the student's ReVSI score (then VSTI, then VSI-Bench) per GPU-hour under the standing rulings, and how would each be killed early?

## Method
1. Read the inputs. Keep S/work/G03/NOTES.md with `record:line -> number` for every number you will use.
2. Build the points ledger (R/files/G03/LEDGER.md): per ReVSI category, the current development score, each measured ceiling, and the category's share of ReVSI items. Take shares only from records, never from benchmark files. Gap times share bounds what a fix to that category can add.
3. Generate candidates from your stance. For each, derive the expected gain as (share of the measured gap the mechanism closes, from a development or K1 measurement) times (category share), as a range, citing every factor. A gain with no measured factor is "unpriced" and ranks below every priced one.
4. Price GPU-hours from the cost basis: about 0.16 H100-hours per training step (134-156 s on 4 H100), about 9.6 H100-hours of preparation per job unless a record shows the stage cached, read costs from the read-kit sizing, and whole 24-hour jobs on Orchard.
5. For each candidate give: the earliest read that can kill it (step, development set, item count, bar); the confounds; the code and data it needs (name the built kit or record, or write "new build"); the rulings that constrain it; and what vehicle N's own reads will already tell (never duplicate N; say how N's first reads change the experiment).
6. Rank by expected ReVSI points per GPU-hour, then by how soon the kill rule can fire. Break ties toward experiments that also serve the second goal (M/lane-intent-two-goals-20261111.md). Keep at least eight and at most fifteen.

Write each experiment in R/files/G03/QUEUE.md as this block:

Also write R/files/G03/queue.jsonl, one object per experiment with keys rank, name, revsi_gain_lo, revsi_gain_hi, priced (true or false), gpu_hours, kill_rule, decides_on, needs_new_build (true or false), rulings (list of note names), records (list of record files cited).
