## Method
1. Normalize. Put every proposal from the three members in one table (R/files/G04/ALL_PROPOSALS.md: member, member rank, name, mechanism, ReVSI gain range, GPU-hours, kill rule, decides-on set). Merge duplicates (same mechanism and decision set) and record which members proposed each; agreement across stances is evidence, not proof.
2. Refute each merged proposal with three tests, each answered with a citation:
   (a) Already answered: does a record settle the question? Cite D/<record>:line and the number; drop it, or keep only the part the record leaves open.
   (b) Inconsistent with a measured ceiling: recompute the gain from the cited factors. If the claim exceeds (measured gap) x (category share), or rests on a lever a record measured flat (for example ANCHOR, closed-model points, mask carry), cut it to the consistent value or drop it.
   (c) Ruling breach: name the note; drop it.
   Also ask (d): will vehicle N's first reads answer it? If so, mark it WAITS-FOR-N with the read that decides it.
   Mark each SURVIVES, CUT (with the corrected gain), WAITS-FOR-N or REFUTED, with the reason, in R/files/G04/REFUTATIONS.md (one row each, citations inline).
3. Rank the survivors by corrected ReVSI points per GPU-hour, then by how soon the kill rule fires. Write R/results/G_QUEUE.md: one ranked queue (at least eight entries if enough survive), each in the members' block format (Question, Hypothesis, Expected gain, GPU-hours, Kill early, Confounds, Needs, Rulings, Relation to vehicle N, Decides on) plus `Proposed by`, `Refutation result` and `Corrected gain`.
