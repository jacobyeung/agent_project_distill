## 1. Question and scope
The reader gives frozen G3T the item's 32 frames and SAM 3 the same 32. K1's stored tower outputs come from 64 dense frames, with depth kept at the 32 anchors. Without training, this kit prices on K1: (A) G3T's poses, depth and lifted boxes at the anchors when its input is 32 against 64 frames; (B) boxes when SAM 3 proposals and lifting use all 64 frames against the 32 anchors; and reports (C) the camera calls on dev-S1. The language model, its prompt, its 32 frames and the response format do not change. This is not lane sb_f64's question (the language model at 64 frames).

## 3. Factors, numbering and scale
- **Context C:** the frames G3T reads. `C32` = the 32 anchors; `C64` = the 64 dense frames.
- **Views V:** the frames that give proposals and lifted points. `V32` = the anchors; `V64` = all 64 dense frames (needs `C64` with depth kept for all 64).
- **Box rule:** `today` = `lift_bestspread`; `obj` = kit 1's frozen object variant, only if it exists.
- **Arms:** (`C32`,`V32`) is the reader today; (`C64`,`V32`) is kit 1's `GS`, built from the stored tower output, so kit 1's A0 is (`C64`,`V32`,`today`); (`C64`,`V64`) is new. (`C32`,`V64`) does not exist: a frame G3T has not read has no depth.
- **Numbering.** A dense slot is a position 0 to 63 in `dense_frames`, in the manifest's order. Anchor k (printed frame number k + 1) is dense slot `anchor_slots[k]`. In all 300 captures `anchor_slots` rises strictly and each anchor's `sha256` equals the model row's frame `sha256` (checked 06:13Z); assert both. A printed frame list holds anchor members only, by printed number; `first` is the lowest; the printed best frame is the anchor member with the largest mask; non-anchor members add lifted points and nothing else. An object with no anchor member prints `not seen`; count these.
- **Labels.** First-seen truth = the first anchor whose GT raster share is at least 0.002, for every arm. Member precision at `V64` is measured on anchor members, because GT rasters cover anchors only; say so in the report.
- **Geometry and scale.** Every arm's geometry is built as the reader builds it, with leg R1's `e2e_reader.geometry.from_tower` (no up-axis refusal): scale = `e2e_reader.stage1.median_ratio(depth_grid[A], depth_conf_grid[A], own_depth)` (R1 source lines 63 to 74), where `A` are the anchor slots of that tower output and `own_depth` is `own.npz`; gravity = the own gravity of `own.npz`. At (`C64`,`V32`) this is kit 1's `GS`. On every capture that has a convert export the `C64` scale equals the stored `scale` of `geometry.npz` (264 of 264 within 1e-4, checked 07:08Z); assert it.

## 4. Part A: context (about 0.5 GPU-hours)

- **Bars (train):** "context pays for pose" if `C64` beats `C32` on the move proxy or on the short-baseline displacement band with a paired capture-bootstrap 95% lower bound above 0 over the 239 train captures (5,000 draws, seed 20261119). "Context pays for pose" is K1 train's choice of the camera change (G3T reads 64 frames for camera calls). "Context pays for lifting" attributes part of the added frame gain to G3T's input; the box arm's frames are chosen by the added frame gain of section 5 alone.
