## Why
Our student (a 9B video-language model with a geometry tower) answers metric spatial questions through short programs that fuse object masks with the tower's depth and pose. On held-out development scenes the masks come from an open-vocabulary segmenter prompted with the object's name on 32 frames, filtered by a learned selector. With those masks the programs beat direct answering only on absolute distance; with ground-truth masks they would win by 20 to 45 points on several types. The audit /scratch/jjyeung/orch_cd/mask_recall/out/NEVER_PROPOSED.md (read it whole, with DESIGN_RECORD.md and RUNCARD.md beside it) finds that 224 of 1,056 needed object instances are never proposed. The largest group, 81 instances worth up to 14.3 points on absolute distance and 12.3 on counting, has no measurable cause (large enough, visible in several frames, name matches): the text prompt simply does not fire. A variant kit for denser thresholds, aliases and tiles is already running on a GPU; it does not test the two ideas below, which do not depend on the text prompt firing:
- **A. Class-agnostic proposals.** Ask the segmenter for every mask in a frame (automatic mask generation, or a grid of point prompts), with no object name. If a class-agnostic mask covers a never-proposed instance, the problem moves from proposing to naming, which the student can do (its yes/no presence signal beats the segmenter's own presence score: AUROC 0.97 against 0.95, see the audit's "Student evidence" paragraph).
- **B. The student's own pointing.** Ask the student where the object is in a frame and prompt the segmenter with that point or box. The user's stated ideal is grounding that comes from the model's own vision encoder.
