# Fix round 4 (h1read kit): a direct-types-only type filter, and partial returns on a cancelled or timed-out read

Work only inside `/scratch/jjyeung/orch_n30/cont_ops/work/h1read/` (this kit). Read REPORT.md, FIX1.md, FIX2.md, FIX3.md and DIFF.md first. No network, ssh, Slurm, GPU, Git or deletion, and no searches outside this folder. Do not modify `kit/build/*` (live production receipts); tests create fixtures only under `evidence/test_*`.

## Why
Job 170928 read family `a7` (R0-dev, 2,169 items) of the step-544 export (run 469ddece, generation mstop, step 544; prepared with `prepare --run 469ddece --namespace 8865619b --step 544 --generation mstop --families a7`). It was cancelled (SIGTERM from scancel) after 70 minutes at 1,958/2,169 items, and it returned nothing usable. Two things went wrong:
1. Step 544 spends about 150 s per item on `object_abs_distance` (159 s) and `room_size_estimation` (147 s), against about 1 s for every other type. These two are routed types; their baselines come from a different evaluator, never from this direct kit. So the read must be able to skip them.
2. The kit packs a family only when it completes. The cancelled job's return (`kit/build/aed15a8b7cb/fetched/result.tar.gz`, unpacked in `fetched/x/`) holds metadata, FAILED.json ("Orchard allocation signal 15"), SPEC.json, a7/ASSET_CHECK.json, a7/a0/{BIND_STATUS,PROMPT_PINS,request}.json and a7/a0/frames, and no journal. The node journal `r/a7/a0/results/0/g0.jsonl` (one JSON line per finished item with status, score, question_type, seconds, output_tokens and more), with 1,958 complete lines, was lost.

## Change 1: type filter (read identity)
- Add an optional prepare argument (for example `--types-exclude object_abs_distance room_size_estimation`, or a named preset `--types direct`, which means every type except those two; choose one clear interface). Without it, behaviour, CONFIG and plan bytes stay byte-identical to today. Prove this with a test that regenerates an existing fixture preparation unchanged.
- Record the filter in the read identity (CONFIG.json, the plan whose sha256 is `plan_sha256`, and SPEC/SUMMARY in the return), so the filtered read and an unfiltered read can never be confused.
- The reader generates only the kept types. Every kept type keeps its full item set and its denominator unchanged; for a7 these are object_counting 385, object_size_estimation 293, the three object_rel_direction levels 192/194/192, obj_appearance_order 246 and object_rel_distance 279 = 1,781 items. Excluded types appear in SUMMARY.json as excluded (with their item counts), never as score 0.
- A family counts as complete, and is packed and returned, when all its kept items complete. Apply the filter to the other families too (main, away, forward), with the same semantics, wherever a type of those two names exists there. If a family has no item left after the filter, refuse at prepare.
- Keep every admission, binding, export, asset, parity and completeness check. The completeness check is relative to the kept item set. Never weaken a check; if one cannot be adapted without weakening it, stop and report.
- Room coverage reporting: report rooms with kept items; the registered room denominator stays as documented.

## Change 2: partial return on cancel, timeout or failure
- When the job stops early (SIGTERM or SIGUSR1 from scancel or the time limit, a chain failure, or an exception), the return must carry the journals each family has written so far (`g0.jsonl` and any `items_a0.jsonl` or summary that exists), marked `"complete": false`, with the count of finished items per family and type. Keep the existing archive cap (89.9 MB production; 19.9 MB proof): if the partial journals would exceed it, truncate cleanly by whole lines, record that in the return, and never fail the publish because of it.
- The job already traps SIGTERM/SIGINT/SIGUSR1 in `orchard_job.py run()` and publishes. Make sure the partial packing happens in that path before publish. A late scancel must not lose everything, and the publish must still finish within Slurm's kill-wait. Measure how long the packing takes on a 1,958-line, about 55 MB journal fixture, and state it.
- `tools/unpack_return.py` and the fetch path accept a partial return and report it as partial (no score is presented as final).
