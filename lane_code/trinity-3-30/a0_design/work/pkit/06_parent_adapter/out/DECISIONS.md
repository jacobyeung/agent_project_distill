# Adapter decisions

All model numbers are pending one reader. Paths below identify the evidence for every numeric setting or count.

- **Substitution scope.** Options: replace every parent key, or replace only parent keys in the native cohort. Default: intersect the native cohort with the parent export, require exactly the distance and room types, and preserve all other rows. Evidence: `IDENTITY_CHECKS.json` and `/scratch/jjyeung/orch_n30/native_r2/work/full_c8r/x/native/R1.json`. The complete script output therefore mixes parent and student direct rows; only the paired type groups are parent comparisons.
- **Label rule.** Options: own answer or released answer. Default: follow the confirmed script, which selects `released_answer` for `primary` and `answer` otherwise. `score` comes directly from the selected parent `scores` entry. Evidence: `/scratch/jjyeung/orch_n30/native_r2/builds/05_analysis_fix/out/native_vs_direct.py` and `/scratch/jjyeung/orch_n30/native_r2/work/parent/r5/merge_results/B2048.json`. No answer is rescored.
- **Identity.** Options: accept key overlap alone, or require metadata, frame and setting checks. Default: require key, exact question type, room, stratum, anchors and frame digest strings to agree. The shared TASKS bytes supply question, options, labels, ground truth and all task metadata. Native CONFIG binds those bytes; parent STRATA binds the labels. Neither native R1 nor parent score rows independently contain question text. Evidence: `IDENTITY_CHECKS.json`, `/scratch/jjyeung/orch_n30/native_r2/work/parent/r3/TASKS.jsonl`, `STRATA.jsonl`, `FRAMES.json`, and `/scratch/jjyeung/orch_n30/native_r2/work/full_c8r/x/metadata/CONFIG.json`.
- **Missing raw generations.** Options: retain student generation fields, invent parent generation fields, or provide a score-only adapter row. Default: provide a score-only row. `FIELD_MANIFEST.json` records every field set and every unavailable student field omitted for each substituted key. Uncovered rows retain their original bytes. Parent generation text, token IDs, extracted answers, timing and prompt text are unavailable.
- **Per-item state.** `hit_token_cap` comes from parent `capped`; `parse_failed` is parent `unparsed OR unanswered`. The adapter checks the per-item values against the kit's zero aggregate diagnostics. Evidence: `/scratch/jjyeung/orch_n30/native_r2/work/parent/r5/merge_results/B2048.json` and `B2048_kit_summary.json` in that directory.
- **Aggregate state.** Options: infer arbitrary per-item flags, or allow only a zero aggregate to establish all-false flags. Default: refuse any nonzero per-type `forced_close`, `stopped_unclosed` or `derivation_error`; otherwise set those fields and `producer_error` to false. This rests on exhaustive aggregate counts, not per-item derivation records. Evidence: `/scratch/jjyeung/orch_n30/native_r2/work/parent/r5/merge_results/B2048_kit_summary.json#/derivation`.
- **Finish reason.** Options: retain the student reason, leave the required field absent, or normalize from parent flags. Default: `length` if capped, otherwise `stop`. `finish_reason_evidence` explicitly states that this is normalized and the original reason is unavailable. This is an analysis compatibility field, not an observed parent EOS record.
- **Fields shared by compact and raw.** All updated compact fields are copied verbatim into the substituted raw row. Original compact identity fields (`family`, `key`, `id`, `question_type`, `room`, `native`, `stratum`, `budget`, `label_policy`) remain intact after validation. `model` comes from the kit; `binding` comes from the parent request; `kit_binding` comes from the kit's distinct budget binding. `adapter_evidence` marks the rows as summary-derived.
- **Additional raw fields.** All fields in the shared TASKS row are copied directly, with the validated compact fields taking precedence. `arm`, `frames`, `layout`, `anchor_indices`, and `answer_cap` come from the kit. `status=complete` rests on the completed/expected count equality and passing kit admission, not an available parent journal. Evidence: `/scratch/jjyeung/orch_n30/native_r2/work/parent/r5/merge_results/B2048_kit_summary.json`.
- **Decode and frame layout.** Default: compare kit budget and continuation answer cap to every available native unflagged decode receipt; allow an absent receipt only for a geometry refusal without decoding. Scripted rows do not expose that receipt. The native CONFIG's representative processor audit must show duplicated anchors and timestamps, with temporal-patch timestamps equal to the unduplicated sequence. Per-item anchors and frame hashes are checked in both native arms. This does not verify per-item processor pixels. Evidence: `IDENTITY_CHECKS.json` and `/scratch/jjyeung/orch_n30/native_r2/work/full_c8r/x/metadata/CONFIG.json`.
- **Artifact interpretation.** Default: run the confirmed CLI with its student EXPORT_ARTIFACT default intact, and explicitly restrict that line's interpretation. The direct arm is cp1m200 by kit summary and request binding. No parent artifact digest is checked. Evidence: `CLI_RECEIPT.json`, `IDENTITY_CHECKS.json`, and `/scratch/jjyeung/orch_n30/native_r2/builds/05_analysis_fix/out/real_parent/NATIVE_VS_DIRECT.json`.
- **Toy output location.** Options: modify the script bytes, write outside this build, or call the unchanged script's CLI entry point after changing only its in-memory output-root constant. Default: the last option, only in the synthetic test. The fixture invokes the adapter and the script's actual `main` parser with explicit fixture paths and subset mode. Production uses a separate interpreter and the unmodified CLI defaults. The test retains its temporary directory inside `out/tests/`.
- **Bootstrap.** Default: use the confirmed script's default seed and draw count for the real comparison. Tests use its minimum accepted draw count. Exact values and source paths appear in `CLI_RECEIPT.json`, `PAIRED_VS_PARENT.json`, and the toy result; no bootstrap implementation is substituted.

The comparison crosses GPU types and prompts by design. Hardware identity is supplied context, not independently verified here. Camera types do not pair because the parent camera read is absent. No borderline project-history prose was retained.
