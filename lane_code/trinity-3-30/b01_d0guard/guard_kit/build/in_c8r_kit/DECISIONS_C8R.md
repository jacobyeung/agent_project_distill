# C8r decisions

- Sharding options: change the production reader/request protocol, synthesize shard completion records in the harness, or preserve the single-process path. Default: preserve the single-process path. `nomdg.run` iterates the complete bound request and emits one completion; `nomdg.merge` authenticates that completion and a complete journal. There is no production shard argument. The harness refuses `--shards` above one without starting work. See `out/SHARDING.md`.
- Transport options: require both channels to succeed or accept either independently verified channel. Default: use the accepted lane publisher's independent-channel semantics; attempt both, report failures, and admit a return only after at least one verified copy. GCS commands execute on Orchard with the family's `assets.gcloud_config`. A bounded `RETURN_RECEIPT.json` sidecar preserves the archive/exit generation and SHA256 readback evidence in each available channel; its publication failures are recorded separately from the core return status.
- Write-probe options: a named helper file with explicit cleanup or an anonymous temporary file in the pool. Default: an anonymous temporary file, confined to the pool, closed by the helper after fsync and SHA256 readback. The parent enforces the deadline using the accepted subprocess pattern. The supplied accepted sources reference `return_io.py` but do not supply its implementation; only that primitive is implemented locally.
- Capacity units: decimal MB for the requested per-mode return caps; retain the binary GiB pool cap. Both archive and receipt/log overhead count. See `out/c8r/FAMILY_C8R.json` for the sealed limits.
- Runtime options: trust PYTHONPATH under isolated Python or explicitly insert the supplied overlays in the controller. Default: explicit insertion, because `-I` ignores PYTHONPATH. All Python commands still set the requested environment and use the specified interpreter and flags.
- Rehearsal storage options: expand the shared inputs again or reuse build C8's staged inputs through read-only namespace binds. Default: read-only reuse, with the new code mounted separately and all output under this build. The harness checks the shared input object descriptors against the new family before reuse.
- Upload fields: retain `PENDING_UPLOAD` for code generation and MD5 until the operator uploads the archive; do not treat a local numeric fixture used by the sealing function as cloud evidence.
- Neutral-name scope: all new external return paths, objects, and logs use the prescribed neutral return roots and opaque token. Immutable input paths and required source/artifact names remain unchanged.
