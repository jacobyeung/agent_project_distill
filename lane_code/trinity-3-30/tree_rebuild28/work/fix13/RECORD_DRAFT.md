# N kit census post-condition: placing pose rows and the protection table (tree_rebuild28 fix13, 2026-11-21)

Question: why does the kit's census publish (b/cs.py, run by b/a.py after the forward) refuse R1_CENSUS_ROOM_UNRESOLVED:pose for every admitted pose row of job 174134, and how should the census place pose rows and treat K1 held-out rooms (ORCH ANSWER 1653Z, RULING 1716Z)?

Answer: pose rows name their scene only by a division token dN/v<12 hex> = carrier_c1_routing.alias_of(canonical) = 'v' + sha256('rung1 scene ' + native/scene)[:12]. Rooms.aliases does not hold these tokens, so Rooms.status yields no canonical and sv.classify raises. The kit fix (fix13 DIFF.patch ed5382ef; b/sv.py 3b6b0ea8, b/cs.py 0fba43e5, b/pf.py 531567f2) looks each pose token up exactly: tier 1 inverts alias_of over every canonical named by the pinned room-authority files, the twin alias list, the dev/benchmark/official lists and the R0/K1/withheld rooms; tier 2 covers the whole ScanNet namespace scene0000_00..0806_09, asserted collision-free. A row that matches nothing or two scenes refuses. Token-form list names resolve to their capture, so lists carry physical-room keys and protect sibling captures. A literal PROTECTION table in b/sv.py says which status protects which stream: benchmark, dev, R0, withheld and official protect all four; K1_heldout protects vqa and pointing; for pose and routing K1 rows are recorded as exposure, not protection. The receipt shows the table, the counts by resolution (authority_and_aliases, namespace, unresolved), the protected counts by resolution, and K1 exposure by dataset, category and s1_source. b/pf.py census() classifies the first 100 rows of every stream source right after staging.
