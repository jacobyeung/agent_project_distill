## 3a. Arm `track`: SAM 3's video tracker as the source of instances (orchestrator order 05:46Z)
- **Pass:** the scene's 32 item frames in temporal order as one video; SAM 3's video predictor with the name as the text prompt (the staged SAM 3 source and `sam3.pt` 9999e234...; the builder confirms that the staged source holds the video predictor and that the checkpoint loads into it, and writes a BLOCKER if either fails; nothing is downloaded). Output per (scene, name): tracks, each with an id and, per frame, a mask on the reader's 80 x 112 raster and the detection score.
- **Instances:** a track counts when its highest detection score is at least 0.3 (the linker's floor). Count = number of such tracks. First frame = the track's first frame whose mask covers at least 0.002 of the raster. Box = the kit's box rules applied to the track's frames (`today` on the track's best frame; `object` fusion over all its frames, without the gather step, since the track already carries the frames).
- **Choice for a single-object call:** cast each track as a linked candidate (one proposal per frame) and run the unchanged selector head with rule `candidates_argmax`; if the selector's featuriser cannot take a track, choose the track with the highest peak score and say so.
- **Order of work, stopping at the arm's 4 GPU-hours:** names of appearance-order items, then counting, then absolute distance, then size, then relative distance. A category the budget does not reach is reported as not priced under `track`.
- **Reported against** the present source (per-frame proposals, linker, selector) on the same items, by the bars of section 5; `track` replaces the present source for a category only on a paired 95% lower bound above 0 there.

## 4. Programs (CPU; the reader's `StageOne` with rule `candidates_argmax`, then the box rule; a `not seen` or `box unavailable` operand makes the program refuse the item)
Box rules: `today` = `lift_bestspread`; `object` = kit 1's gather and winning fusion rule, only if kit 1's first bar passed.
- **Absolute distance (290):** two grounds and `box_grid_5cm`, as the reader prints it; metres. No direct answer exists at step 200 for these items, so this row is the head's own score on unexposed ScanNet++ rooms under each box rule, reported against the constant (29.5) and against leg D0's step-200 direct read of the same items (`san_kit` root `('D0', 200)`) as context, not as a paired decision.
- **Size (293):** longest edge of the printed box, in the question's unit.
- **Relative distance (279), two-candidate check:** parse the direct trace's stated order (the line "the nearest-to-farthest order from the X is: A, then B, then C, then D"; it parses on 279 of 279 step-200 traces); take the two candidates it places nearest the asked end (closest or farthest); compute the box gap from the reference object to each; answer the one the gaps favour; if any of the three grounds refuses, or the trace states no order, keep the direct answer. Also report the full program (gap to every option) for reference.
- **Appearance order (246):** the first printed frame of each named object; the option whose order equals the order of those frames; ties broken by the order in which the two objects' lowest-index proposals appear; if an object is not seen or no option matches, keep the direct answer. Report the strict program (refusal scores 0) beside it, and per object: first printed frame against `gt.first_pos_f32`, exact and within one, and the share of object pairs ordered correctly (the trace's own stated frames: 78.2% of 1,476 pairs, and the true order on 86 of 246 items).
- **Counting (385), diagnostic:** the number of gathered objects for the name (`object` rule), and the number of tracks (`track`), against the truth and against the direct answer (53.7 at step 200) with the paired interval, split by truth (2, 3, 4, 5 or more); the route decision for counting belongs to lane sb_countdesign's record.
Each program is scored by the item's own rule (MRA for numeric, accuracy for choice), with the scorer the direct read used.

## 5. Statistics and bars, written before any number
Paired differences head minus direct on the same items; 95% percentile bootstrap over rooms, 10,000 draws, seed 20261119; item-weighted means; ReVSI points = category points / 7 with the subtype weights of the trace analysis, section 11.
- **Size routes** if head minus direct is at least +5.0 type points with a lower bound above 0. **Stays direct** if the upper bound is below 0. Otherwise undecided, which means direct. (Run size only if kit 1's size screen passed or the `object` rule exists; with `today` alone the expected result is the 50.7 against 73.6 already measured, so report it without a decision.)
- **Relative distance, two-candidate check, routes** at +3.0 with a lower bound above 0; the check can change an answer only where the gaps disagree with the trace, so also report how many answers changed, and how many of those became right and wrong.
- **Appearance order routes** at +5.0 with a lower bound above 0 for the fallback form. Run it only if kit 1's first-seen screen passed; otherwise report the per-object first-seen rates alone.
- **Absolute distance:** no bar against direct here. The `object` rule is confirmed on unexposed rooms if it beats `today` with a paired lower bound above 0; a loss with an upper bound below 0 withdraws kit 1's PASS.
- **`T94`** pays if absolute distance under `T94` beats the 32-frame arm with a paired lower bound above 0 (same box rule). **`da3_f32`** is reported beside the primary arm and decides nothing in this kit.
A route verdict here licenses a build of rows and a reader read for that category; it is not a benchmark claim.
