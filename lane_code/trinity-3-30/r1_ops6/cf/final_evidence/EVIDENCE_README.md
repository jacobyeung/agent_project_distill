# Evidence for the R1 counting diagnosis and fix (lane count_diag, 2026-11-18)

Every figure in `R1_COUNTING_LOSS_DIAGNOSIS_20261118.md` can be recomputed from this archive. Tables that need the original reads or the row store say so and name the script that built them on trinity-1-3. `SHA256SUMS` lists every file.

## The five items the orchestrator asked for (ORCH NOTE 1110Z)
1. **Form classifier:** `classify_counting_rows.py`. It reads store v7 (rows.sqlite 210b2534, `?immutable=1`), `n.json` 02315a74 and A2 v3 `CHANGES.jsonl` 56100b66, and it regenerates the three REMOVE lists byte for byte (`CLASSIFY_SUMMARY.json`). The docstring states its rules.
2. **Per-row membership table for B1 against store v7:** `MEMBERSHIP_V7_COUNTING.tsv`, built by the classifier. It has one line per object_counting and first_seen_frame row (27,745) with i_v7, qid, pool, cell, form, list entries, repeats, max run, answer, in_n_json, in_B1, in_B1_keepD0totals, in_A, in_restore, scene and target_sha256. B1 is exactly the lines with in_B1 = 1 (17,879). After n.json and B1, the counting cell keeps 2,617 rows (all PROC) and totals keep 0.
3. **Entry repetition behind "29% of entries":** `REPEATS_BY_FAMILY.json`. r1g lists hold 20,320 entries, 5,959 of them repeats (29.33%), and 3,295 of 6,636 rows repeat an entry. The file also gives the counts by list length and for b12 single, b12 totals and the D0 gap totals. Recompute from `v7_cf_compact.jsonl` (targets of all counting and first-seen rows) or from the store with the classifier.
4. **Per-read runaway classification for each export:** `RUNAWAY_BY_ITEM.tsv` (2,525 lines; built by `build_runaway_table.py` from the reads named in `RUNAWAY_SOURCES_SHA256.json`). Each line gives export, set, item, room, multi-category flag, truth, B2048 answer and score, step 544's score on the item, B2048 forced close, 16k cap, 16k output tokens, trace form, list entries, list repeats and the entry where a run of 10 identical entries starts. A runaway is a B2048 forced close.
5. **Recomputed losses:** `recompute_losses.py` reads `RUNAWAY_BY_ITEM.tsv` alone and writes `LOSS_RECOMPUTE.json`: runaway counts per export (single and multi), each export's change against step 544 with its room-bootstrap interval, R1's decomposition (runaways -6.53 of -8.27 on dev-S1, -6.62 of -4.10 on R0-dev), and the counterfactual with runaways scored as step 544 (-1.73 [-8.07, +4.30]; +2.52 [-1.06, +6.14]).
