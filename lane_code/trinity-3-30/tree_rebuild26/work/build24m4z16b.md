## Build `J/out/jn6.sh` from jn5.sh (nothing else in the wrapper changes: SBATCH header incl. --mem=800G, ROOT=$X/n, child job.sh with TERM/USR1 forwarding, the EXIT trap, bounded final publish and fallback of jn5)
1. Live mirror: a background loop in the batch shell (not srun), started right after the node directory exists, every 120 s writing atomically (.part + mv) into `$X/o/${SLURM_JOB_ID}_live/` (mode 700): `mem.txt` (memory.current, memory.max, memory.peak if present, memory.events, and the anon/file/shmem/file_dirty/file_writeback/kernel lines of memory.stat, for the job-level cgroup found by walking up from /proc/self/cgroup to the `job_<id>` directory, plus the step level); `df.txt` (df of the node job directory, of /tmp and /dev/shm); tails (last 64 KiB) of the kit's q.log and q.steps and of the node-local Slurm .err (find their real paths in the kit and jn5; name them in the report); and once each, when present, copies of the kit's v.json, WAITING_REVIEW.json and f1.json (each under 1.5 MB, else record the size only); a `gate.txt` line with the gate state (waiting since, review.json present or not) when WAITING_REVIEW.json exists. Directory total under 2 MB (skip and note otherwise). Memory alarm: page cache is expected to fill the limit (173964 had memory.current at 800G with anon under 3.1 GiB and shmem 0), so the alarm reads anon+shmem, not memory.current: when anon+shmem of the job cgroup exceeds 80% of memory.max, or when the oom or oom_kill count in memory.events rises, append one line `MEM_ALARM <UTC> <current> <max> anon=<> shmem=<> file=<>` to `alarm.txt` in the same directory (once per crossing). The loop never fails the job (no set -e inside, each command under `timeout 30`), never blocks the EXIT trap, stops when work ends, and takes one final snapshot inside the EXIT path before the final publish (bounded by timeout).
