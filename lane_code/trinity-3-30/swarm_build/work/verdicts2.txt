## Blockers
1. **The rollout crashes on its first draw.** `rollout.py:23-24` passes `trace_program_version=` to `carrier_c1_decode.generate`, whose signature (`carrier_c1_decode.py:454-455`) has no such keyword, so the call raises `TypeError` (`runs/patched_signatures2.py`). N's evaluator selects 3.14 through the model and backend alone (`evalpath/run.py:350-357`). Edit: delete the keyword (`PATCH_rollout.diff`). The patched call binds.
2. **The reward scorer fails parity with N's official per-item scorer.** `reward.py:37-40` uses the strict diagnostic parser `parse_answer_v1` and picks the answer type from whether options are present. The official scorer, `evalpath/run.py:70-80` (`score_item`), uses fuzzy first-token extraction and infers the type from the question type. On 74 answer formats, 32 differ (`runs/parity.out`). In 28 of them the kit pays 1.0 where the official scorer pays 0 (`about 12.19`, `12.19m`, `**B**`, `The answer is B`, `(B)`). In 4 of them the kit pays 0 where the official scorer pays 1 (`b`; a choice type stored without options). RL would learn formats the benchmark scores as wrong. Edit: compute correctness with `score_item` (`PATCH_reward.diff`), and give `test_choice_exact` a choice type (`PATCH_test_kit.diff`), because it now scores a choice answer under numeric `room_size_estimation`. After the patch, parity is 0/74 mismatches and tests pass 20/20.
3. **A fake early `</think>` evades the length penalty.** Length is measured up to the first `</think>` (`reward.py:34`), but the official scorer reads the answer after the last one. A 1,500-token thought placed behind a fake early close earns short = 1 and total 1.2 (`runs/double_think.py`). Edit: `if text.count('</think>') != 1: short = route = 0.0` (in `PATCH_reward.diff`). The fake now scores 1.0, below the honest 1.1.
4. **The rollout reads camera pose from a different source than N's routed reader.** The kit decodes with `pose_source='tower'`, which overrides pose with frozen G3T output (`rollout.py:23`, `train.py:82-84,110-111`). N's evaluator calls `generate` with the default `pose_source='own'`, the student's own pose head (`evalpath/run.py:355`, `runtime.py:152-165`, `carrier_c1_decode.py:143-170`). Edit: default to `pose_source='own'` and drop `tower_state`, `tower_batch`, `prepare_tower` and `attach_tower`, or record an orchestrator ruling that the deployed reader is `tower`.
5. **One bad draw aborts the whole run and loses everything.** Sampled calls raise `RowRefusal` when a call runs past `max_call_tokens`, past 40 calls (the evaluator allows 200), or past the token budget (`carrier_c1_batch_decode.py:133-155`). `tower_item` catches only `TowerError` (`tower_errors.py:29-34`), and `train.py:117-119` catches nothing, raising even on `tower_error`. Adapters are saved only after step 200 (`train.py:135-140`). Edit:
   - Wrap `sample` in `try/except RowRefusal`, and score a refused or tower-error draw as reward 0 with no backward pass.
   - Replace DDP and `no_sync` with zero-initialized gradients plus `torch.distributed.all_reduce(p.grad); p.grad /= world` after each step, so a skipped draw cannot hang the collective.
   - Save adapters and optimizer state every 25 steps and log refusal counts.
