## Footguns learned
- CPU checks that only import or use controlled outputs miss real paths; require CPU end-to-end runs and replays of real card outputs. For a job family: run the worker's own functions end to end on CPU with stand-ins only at the GPU boundary, with line coverage, before the first submission; nine routed-read attempts each died on one unexecuted line or stale pin.
- A file that is pinned in several places (code pins, bootstrap pins, an asset's entrypoint, an archive member, a cache's producer hash) goes stale in whichever place the builder copies forward. When comparing two seals, question any changed file whose copies did not all move.
- An independent Claude pass over the whole path (pin audit, CPU replay of the reference arm over all items) took 15 minutes and found what the next pilots would have found. Order it before the first submission, not after the fifth failure.
- Do not narrow a lane's own pre-submission check to save time; my narrowed scope caused one failed pilot.
- Read the sample series before attributing a disk or space change to someone else (I told main a drop was another tenant's when it was our own end-of-run save).
- A default I wrote in an unanswered saved question is not the user's approval. A new allocation, a new arm beyond the registered ones, or any spend the user gated needs the user's answer; build the packet and hold it.
