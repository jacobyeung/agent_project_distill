# MDG routed-read kit: routed v3.11 programs on MDG masks vs direct answers (lane mdg_next, 2026-11-09)

## Question
If MDG-A passes (Tue ~06:00Z), does routing the object-type questions through the v3.11 programs, with MDG masks as the clicks, G3T x s pose and the model's own depth, beat the same model's direct answers? The kit must be ready before the read, run on trinity-0-18 (8 x A6000) or Orchard (4 x H100), and keep ground truth out of inference.

## Answer
- **Kit:** `/scratch/jjyeung/orch_cd/mdg_next/work/rkit` (own git; package `rk`; contract `work/RKIT_SPEC.md`). One command: `RK_GPU_GO=1 ./run_read.sh CONFIG.env` runs anchors -> export (GPU) -> G3T (GPU, ReVSI only) -> heads -> programs -> report.
- **Sets:** dev 858 (84 held-out ScanNet val scenes; direction medium/hard, abs distance, rel distance) and the 281 ReVSI cap71 object questions (155 scenes; direction 68, abs 71, rel 71, size 71).
- **Routed arm:** SPEC v3.11 frame choice (common frame by larger minimum mask area then lower frame, else the visible pair minimizing (|i-j|, i, j); direction anchor = frame with most named objects) on all 32 per-frame views; closest points between lifted eroded-mask point sets for abs and rel distance; direction from median mask-point centres; size from a gravity-aligned box. Executor: evalx `tp/programs.py` primitives with `rk/scheme.py` overrides (the reference executor hard-codes fitted-box centres for direction, so direction runs in `rk/scheme.py`).
- **Geometry:** G3T poses with t x s, s = median(own depth / G3T depth) by ttower's frozen rule, rotated into the base's own gravity frame; FoV from G3T (default, as in ttower's heads_g3s64_vcd) or own; depth = the base's own private depth on a 51 x 51 grid. The heads builder reproduces ttower's `heads_g3s64_vcd` to 1e-9 on 10 scenes.
- **Export:** one carrier prefill per clip on the base export gives both the MDG masks (unchanged `mdg_eval` schema) and the own heads (pose, gravity, depth); on the tiny model the own heads equal `CarrierC1.readout` within 1e-6. An MDG artifact trained on another base (CP1 m200 read with the T0-trained decoder) needs `CROSS_BASE=1` and is labelled in every audit.
- **Direct arm:** the base's own answers per item: dev `evalx/work/pulled5/dd_<base>.jsonl`; ReVSI `evalx/work/pulled5/tr_rv_<base>.jsonl` (evalx's 0-13 reads).
- **Statistics and rule:** per type, routed+fb (program, or the direct answer on refusal) minus direct, item-paired, scene bootstrap 95% CI (4,000 draws, seed 17). Routing wins a type when the CI lower bound is above 0; GO for stage B / evaluation flags when it wins >= 3 of the 4 dev types. ReVSI reports the same rule as a transfer read.
- **Operands follow SPEC v3.11 eligibility:** eroded masks (1 cell at 80 x 112), clicks in [20, 980], spread <= 0.10 within 40 grid units of an edge else <= 0.25, complete closest-point pools; a rel-distance candidate without eligible operands refuses rather than losing.
- **Primary row = ungated programs; secondary row = SPEC section-9 own-value gates** (near tie < 0.10 m or 10%, floor vector < 0.50 m, within 10 deg of a label boundary; refusals fall back to direct). Chosen before any MDG data: on the GT-mask oracle the gates refuse 28-34% of direction items and cost 0.9-4.5 points of routed+fb.
- **Oracle ceiling (GT masks in place of MDG, same geometry, T0 m800 direct; routed+fb, ungated):** dev direction medium 84.4 / hard 82.6 / abs 67.8 / rel 89.7 vs direct 60.3 / 58.7 / 28.2 / 62.4; all four CIs > 0, refusals 2-7%. Gated: 79.9 / 81.7 / 67.8 / 87.9. MDG's masks must recover enough of this gap.
- **SAM 3 masks through the same read (CPU, `rk/sam3mask.py`; routed+fb - direct, medium / hard / rel / abs):** zero-shot with its frozen accept rule -13.0 / -22.6 / -29.7 / -3.8 (0 of 4); GT frame presence x top instance +8.9 / +7.8 / +7.3 / +27.3 (1 of 4); GT mask choosing among SAM 3's instances +22.8 / +26.1 / +24.9 / +38.1 (4 of 4, at the GT-mask ceiling). SAM 3 proposes the target (best-instance IoU > 0.5 on 71.5% of GT-visible label-frames) but ranks distractors first; only 47% of its accepted frames overlap the target. T0 m600 marker clicks (57% in-mask, evalx ground_t0m600v) choosing the instance give +3.6 / -0.9 / -2.4 / +17.5 (abs distance wins with no GT and no MDG), so the gain scales with the selector's placement. An ORACLE placement curve (GT presence; selector = GT mask or a SAM 3 instance missing the target) wins 1 of 4 types at 50% and 65% in-target selection, and 4 of 4 at 80% (+11 to +30) and above; the prediction before the MDG-A read is that s3i passes when MDG-A's in-mask rate reaches about 75-80% with its null rate intact. The read's extra arm `s3i` lets the MDG masks pick among SAM 3's instances (no GT): a coarse but correctly placed MDG mask can then borrow SAM 3's extents.
- **Real-model CPU first batch (stub decoder on T0 m800):** one clip takes 28-30 min on CPU (prefill 1,408-1,502 s, own heads 212 s, RSS 43 GB). The own heads from the kit's single prefill match ttower's GPU heads_g3s64_vcd for scene0011_00 (depth median relative difference 0.1%, pose 0.3%). Every CPU stage (heads, programs ungated and gated, report, s3i) runs end to end through `run_read.sh`.

## Why
- The CP1 routing table and TOWER-0 found the clicks, not the programs, bind routing: GT clicks + own depth beat direct by +11-20, own clicks lose. Masks add extents, so closest-point distances become possible (GT interior points cap abs distance at 31.3 vs 56.9 with edges, evalx 0744Z).
- G3T x s pose beats own pose by +22-36 points on the camera types (evalx 1150Z), and ttower's P bar passes on unseen scenes.
- Pairing against the base's own direct answers isolates the routing decision the trainer would make for that model.

## Options considered and rejected
- **Full routed decode (the LM emits `<ground>` calls).** Rejected for this read: no current export was trained on MDG calls, and HF routed decode costs ~1-1.5 h per 150 items on 4 GPUs (evalx 1106Z). The harness answers the stage-B question (are MDG masks worth routing on) at ~1/10 the cost.
- **mdg_build's W10 read alone.** It covers dev with ttower's SAM 3 W10 programs and tuning-fitted parameters; this kit adds v3.11 frame rules, ReVSI, the base's own depth for any base and the paired decision rule. Both reads should agree in sign.
- **Own pose.** Rejected as primary (G3T x s wins on every camera type); own pose remains a fallback if G3T weights do not reach Trinity.
