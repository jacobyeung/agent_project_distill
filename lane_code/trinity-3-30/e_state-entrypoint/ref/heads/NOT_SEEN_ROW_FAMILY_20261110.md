# What a training trace does after the grounding tool says "not seen" (2026-11-10)

## Question
A v3.13 row calls `<ground obj="NAME">` (or `mode="box"`) and the response is `NAME: not seen`. What should the rest of the trace do, which row family should be built first, and how is it tested? Scope: the four routed object types (object_abs_distance, object_rel_distance, object_rel_direction_medium, object_rel_direction_hard).

## Answer
1. **Build family A ("search, then continue") first.** After a first-pass `not seen`, the trace issues one escalated call, `<ground obj="NAME" search="all">` (box mode: `<ground obj="NAME" mode="box" search="all">`), which reads every one of the 32 frames at full resolution, and then continues the normal v3.13 program. Every number comes from a tool response, and all of it runs inside the forward pass.
2. **Every natural miss we have is an object that is visible in the student's frames.** All 5,157 natural misses (abs 970, rel 3,665, medium 236, hard 286) passed the census's GT visibility gate, so each operand has GT presence >= 0.5 and a nonempty mask in at least one of the 32 frames. **Zero** natural misses have an operand that is visible nowhere in the 32 frames: the gate refused 0 of 54,994 inputs. The miss comes from the GT adapter's eligibility rules, not from absence. Full-clip visibility is not recorded in any file.
3. **The terminal branch for a truly absent object stays unbuilt** until test T1 measures how often benchmark operands are absent from the 32 frames. When it is built, use the tool-sourced elimination (c) for relative distance. Do not use the direct estimate (d) unless the user rules otherwise (decision below).
4. **Retire the simulated 10% miss branch for these four types.** Its continuation exists for only 87 of 5,157 natural misses, and readers graded its rendered rows DEFECT 20/20.

## Evidence
- **Counts** (`/dev/shm/jjyeung_ground_size/out/dispositions.jsonl`, reason `render:missing_direct_canonical`): abs 970, rel 3,665, medium 236, hard 286, total 5,157. Natural miss rate among rows that reach rendering: abs 16.0%, rel 29.5% (four or five operands per row), medium 2.4%, hard 2.8%, pooled 13.4% (5,157 / 38,617).
- **Visibility:** `size_full.py` refuses `object_not_visible_drop` unless every operand has GT presence >= 0.5 and a nonempty mask in at least one of the 32 frames. Its `visible` gate equals `exact_name` in all four types (census.json), so every operand of every miss is GT-visible in the student's frames.
- **Why the tool misses.** Box mode builds each instance raster at 80 x 112 with a 0.2%-of-frame area floor (`GTInstances` in `derivgen_v7/derivgen/ground_v313.py`). Lifting then applies a 3x3 erosion, the [20, 980] crop, finite positive depth, and a spread limit of 0.10 at the image edge and 0.25 elsewhere (`backend_v3122/ground_lifting.py lift_object`). Box mode also returns `box unavailable` when the largest-area frame has no eligible points. The disposition reason does not separate `not seen`, `box unavailable` and `unresolved`; for distance rows it records any first-operand failure.
- **What the older rows did** (`/dev/shm/jjyeung_orchard_cp2/fg/r10/rows.sqlite`, v3.8 point-click routing). 5,012 of the 5,157 natural-miss inputs have an older row; the 145 absolute supplement rows have none. All 5,012 click every operand and contain no miss phrase. The older format therefore never saw a miss: the GT clicker always found a pixel. Relative-distance misses get 4.5 click points per row against 12.1 in admitted rows, and 81% of their clicks fall within 40 grid units of the border against 36%. Those objects are small or cut off by the frame edge. In abs and direction rows the edge share matches the admitted rows (36% vs 35%, 8% vs 9%), so area, not the edge, drives those misses. This is one point on the crop corner. The v3.13 adapter finds no eligible point for this object.
  - `q5d5f018981597a66d03fdc5f` (hard): "I click the banana in frame 19. <depth_at frame=19 pts=[[380,206]]><tool_response>P3: cam19 (-0.21, 0.39, 1.30) m; f1 (2.55, 0.04, 3.46) m; spread 0.01</tool_response> ... theta -55 deg; front-right ... That matches option D." The banana is clicked in one frame and is a small object.
- **The deployed tool misses the same kind of object.** Base Qwen's in-mask rate is 21.9% below 1% of frame area and 80.7% at 5% or more (GROUNDING_OBJECT_FIRST_SVP). MDG-A misses mostly objects of 4 decoder cells or fewer (INDEX row 65). Asked for a box, base Qwen draws one on 92% of absent frames; asked yes/no, it says yes on 7.5% (result-presence-pose-routing-20261110). A trained not-seen outcome followed by a targeted search therefore matches the measured failure.
- **The current miss branch cannot be built at scale.** It needs an admitted, exact-matched VQA canonical continuation, and the join file covers 87 of 5,157 (FULL_POOL_SIZE). The rendered simulated misses printed numbers that no tool produced and were graded DEFECT 20/20 (RESULT_ground_v6).
