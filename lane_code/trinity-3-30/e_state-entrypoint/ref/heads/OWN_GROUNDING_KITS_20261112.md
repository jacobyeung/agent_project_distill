The question is whether a required instance that text-prompted SAM3 never proposes can enter the mask pipeline through a category-free point grid or the student's own pointing.

Both paths have runnable adapters and CPU-tested interfaces. No recovery result or GPU timing has been measured here. The audit fixes the denominator at 1,056 operand instances in 93 GT-covered captures, including 224 never-proposed instances and 81 unexplained misses. The proposal workload covers all 152 captures; the other 59 support pricing but have no GT recall measurement. `FEASIBILITY.md` identifies the staged APIs and training evidence by file and line.

The preregistered decision for A uses the 81 unexplained misses. Build naming further only if at least 25 have a proposal with IoU > 0.5 in a usable GT frame, including at least 15 with matches in two usable frames. Stop this configuration if at most eight recover. Other outcomes are inconclusive. These thresholds require roughly 31% recovery and multiview evidence before spending on naming. They do not convert the ideal-mask grant into a predicted score gain. The decision file checks the full denominator before issuing a verdict.

A uses 16×16 cell-centre positive point prompts, 16 independent prompts per decoder batch, three masks per point, predicted IoU ≥0.80, stability ≥0.90 at logits ±1, at least 16 input pixels, mask-IoU suppression above 0.90, and at most 64 masks per frame. It encodes each image once. No category or GT enters generation or ranking. SAM3's interactive decoder bypasses text presence entirely. The source and checkpoint must match the baseline pins; the loader also refuses missing interactive weights, which the upstream non-strict loader would otherwise tolerate.

The compact cache retains the baseline `sam3-svp-cache-v1` NPZ/JSON/RLE structure. A has a reserved `__all__` phrase; B and the GT control have ordinary phrases. Every record retains original frame index, PNG hash, full input raster and explicit score semantics. Interactive `score` and `joint_score` store clipped predicted IoU; `source_presence=1` is a structural sentinel, never a measured presence score. Original quality and stability remain separate fields. Semantic naming occurs afterward.

The cheapest optional naming experiment reuses the existing V1 padded RGB crop and first-token yes/no reader. It queries each needed name against the first eight quality-ranked masks per frame, with no GT shortlist or fit. `p_yes>0.5` admits a mask; other masks remain unnamed. A complete run has at most 209,664 requests, versus 1,677,312 if all 64 masks were named. The exact count depends on A's retained proposals and appears in the naming receipts. The oracle report records each matching mask's rank and shortlist-eight recall, so a shortlist failure is visible separately from a naming failure. The previous crop verifier was weak (candidate AUROC 0.58 mean / 0.69 max); its transfer is a hypothesis. The 0.9741 full-frame presence AUROC cannot be claimed for this task. Frozen selector geometry features already exist, but they cannot independently assign a category to an unlabeled mask. The kit reuses them to link and select named proposals, without fitting on this development set.

B freezes 22,393 (capture, name, frame) requests from the baseline's accepted masks. A request is needed when a required unique-object or counting path has no nonempty accepted mask at that frame; the union avoids duplicating student reads. This schedule uses selector output only, not GT. It can miss a second instance when another instance of the same name already has an accepted mask. Only 69 of the 81 unexplained misses have a usable view in the schedule; 185 of the 224 have any visible scheduled view. These are coverage ceilings, not recovery predictions.

CP1 m200 is the primary pointer, parameterized by an authenticated local full-weight export so later checkpoints use the same requests. Its recipe includes pointing loss and point/null targets. A no-training CP1 control would be false. The primary request uses the inherited video prompt, 1-based frame slot, 32 anchors duplicated into 64 processor frames, true source FPS/timestamps, and trained `Frame k:` markers. The timing authority comes from `devs1_direct/out/r3/TIMING_AUTHORITY.json`; the tower plan's fallback FPS is unsuitable. The reader uses the native vision/language model, no geometry-carrier injection. `--layout image` is a separately bound, cheaper reread transfer experiment, not the inherited video training layout. Source format, checkpoint provenance and capability do not establish held-out quality.

The parser admits one JSON object containing only an integer point in [0,1000]², or null. It permits an empty think prefix or one JSON fence; it refuses malformed output, extra keys, lists of instances, duplicate keys, booleans, decimals, out-of-range coordinates, and capped output. It keeps [0,0], which the training grid can represent; it does not inherit the older reader's arbitrary near-origin rejection. Null/refused answers stay in the request denominator and produce no mask. Pixel conversion clamps the 1000 boundary to the final pixel. The decoder accepts boxes, but the trained answer format does not teach boxes, so B does not silently reinterpret box text.

The GT-centre control makes 4,256 prompts on exactly B's scheduled visible instance-frames. It selects the foreground pixel nearest the GT centroid, then maps its centre from the half-resolution GT raster to input pixels. A concave object's empty bounding-box centre is not a valid ideal click. The control labels each prompt with its GT instance ID, uses the same decoder and thresholds, and is scored as an upper-bound diagnostic. It bounds a perfect centre pointer on this schedule; it is not a mathematical maximum over every possible click. No GT point enters student requests or predicted naming.

CPU analysis reuses the audit's greedy one-to-one IoU >0.5 convention at the half-resolution GT raster. Every target gets frame-level overlap, usable-frame counts, full candidate counts and naming rank. The report separates all targets, never-proposed targets, cause groups, and the known ceiling-light→ceiling binding error. It retains the original denominator for parity and writes a sensitivity route table excluding questions exposed to that error.

Pricing starts from the baseline's selected masks, preserving every baseline raster. The oracle arm adds actual proposal rasters, with GT naming and identity association; it never replaces them with GT shapes. This is an optimistic naming/identity upper-bound experiment, not a mathematical score bound: mask unions can still hurt. The predicted arm uses the frozen linker and selector on named proposals and merges them with baseline tracks only where shared frames provide mask overlap. Quality-as-score is outside the selector's original text-score distribution; its acceptance and counting behavior need measurement. The existing frozen program functions produce per-item results. The existing route tool provides identical-item comparisons and 10,000 physical-room bootstrap draws beside baseline. Oracle and GT-control verdicts are explicitly diagnostic. A deployment change requires positive paired program intervals and a route-versus-direct interval above zero; oracle recall alone cannot authorize it.

Options considered and rejected:

- A native automatic-mask generator is absent from the staged tree. The point grid uses an existing, pinned API instead of assuming an unavailable class.
- Text aliases, thresholds and image tiles are already another experiment and still depend on category prompting. They cannot answer this question independently.
- A 32×32 grid or uncapped mask set multiplies cost and storage. The registered 16×16/cap-64 test measures whether the mechanism has enough signal first. A dead result applies to these settings; it does not prove that every denser configuration is impossible.
- Naming every mask initially costs up to eight times the shortlist pass. The reported rank distribution will show whether that expense could recover missed targets.
