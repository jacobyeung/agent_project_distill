# Lane code sync to GitHub (2026-11-16)

**Question.** How does agent-written lane code on node-local /scratch reach GitHub within about an hour, so a dead node loses no code?
**Answer.** An hourly loop on trinity-3-30 (tmux `lane_sync`) stages whitelisted source and records from `/scratch/jjyeung/orch_n30/*/` on trinity-1-3, trinity-1-18 and trinity-3-30, plus orch_n30 `tools/` and `briefs/`, secret-scans them, commits them to branch `lane-code` of `git@github.com:jacobyeung/agent_project_distill.git`, and pushes the same branch into `/home/jjyeung/agent_project_distill` (never main, never its working tree).
**Status.** RUNNING since 2026-11-16 11:20Z; first sync = commits e9f2226..e6173c6 (4 parts), verified on GitHub by `git ls-remote`.

## Where
- Script: `/data2/jjyeung/agent_project_data/distillation_orchestrator_20260918/orch_n30/tools/lane_code_sync.sh` (+ `lane_code_filter.py`, `lane_code_scan.py`); the same files are `tools/` on branch lane-code. `--dry` prints counts; `--stage-only` stops before git.
- Clone `/scratch/jjyeung/distill_sync/repo` (branch lane-code, remotes origin = GitHub, home = /home repo); stage `/scratch/jjyeung/distill_sync/stage/<node>/`; log `/scratch/jjyeung/distill_sync/sync.log`; flagged lists `/scratch/jjyeung/distill_sync/flagged/`.
- Branch layout: `lane_code/<node>/<lane>/...`, `lane_code/orch_n30/{tools,briefs}/`, and `lane_code/<node>/code_sync/meta/DEDUP_<node>.tsv.gz`.
- Failure: one log line plus `events/code_sync/<UTC>_BLOCKER_sync_failed.md`; the next attempt is the next hour. Remote nodes are reached by one `tools/tssh.sh` call each per run; files stream as `tar | ssh trinity-3-30.ib` (InfiniBand, no NFS, no governor stream).

## Filter (lane_code_filter.py)
- Extensions .py .sh .md .json .jsonl .yaml .yml .toml .cfg .txt .patch .diff; at most 512 KB a file, and .json/.jsonl at most 64 KB (bigger ones are data rows or result dumps). Symlinks skipped.
- Path exclusions: out/devin_traces, /dl/, /root/, /envs/, site-packages, __pycache__, .cache, node_modules, *.sqlite, .git, any directory name containing "frames", any directory with more than 2,000 entries.
- Directory-name exclusions (scratch copies, test and mutation outputs, caches, vendored libraries, data): tmp*, retained_*, rows_*, slices_vN, *proof(s), *_proof, artifacts, r2_<8 chars>, rec_vN*, *_stale, *_prev, cmp_*, test_products, results, clone, mutation*, mut, mut_*, *_mut, round_*, *cache*, scipy, numpy, torch, *.dist-info, *.egg-info, runs, evidence, transactions, envN, venv, .venv.
- Content dedup per node: only the first copy (sorted walk) of each distinct content is sent; every later identical copy is listed in `DEDUP_<node>.tsv.gz` as `dup_path<TAB>kept_path`.
- First run without these cuts: 6.3 GB (1-3), 1.0 GB (1-18), 0.58 GB (3-30). After: 101 MB / 13,342 files (1-3), 44 MB / 7,104 (1-18), 26 MB / 4,509 (3-30), 0.4 MB / 79 (tools, briefs); 171 MB in all, 25,038 files.
- Files removed upstream stay in the branch (the stage is never pruned), which keeps their history.

## Secret scan (lane_code_scan.py)
Private-key blocks, AKIA, hf_, sk-, ghp_/github_pat_, AIza, the quoted private-key JSON field, credentials or token parameters in URLs, literal Bearer values, `*_API_KEY=`/`*_TOKEN=` literals, and the values of key environment variables. A flagged file is never copied into the clone; the list goes to `flagged/`. First run flagged only `orch_n30/briefs/code_sync.md` (names the private-key field in prose) and an older staged copy of the scanner itself.

## Restore a lane's code
`git clone --branch lane-code --single-branch git@github.com:jacobyeung/agent_project_distill.git r` (or `git -C /home/jjyeung/agent_project_distill show lane-code:<path>`), copy `r/lane_code/<node>/<lane>/` back, then recreate deduplicated copies: `zcat r/lane_code/<node>/code_sync/meta/DEDUP_<node>.tsv.gz | grep -P '^<lane>/'`, and for each `dup<TAB>kept` copy `lane_code/<node>/<kept>` to `<dup>` (paths relative to that node's orch_n30). Excluded classes (data JSON over 64 KB, mutation copies, test outputs) are not recoverable from GitHub.

## Options rejected
- Clone the /home repo directly: reads ~32 MB of loose objects from /home; cloned main from GitHub instead (2.7 MB).
- One first push of all 171 MB (~42 MB compressed): over the 20 MB unregistered limit for head-node transfers and /home writes; pushed as four commits of 8-13 MB compressed, one at a time. Hourly increments are small.
- A ratelimit.py-governed git push: git's ssh pipe cannot start stopped as the governor requires.
