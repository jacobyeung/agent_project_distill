- So the rows' "locate X, first seen in frame f" is the only honest citation for most objects, and a rebuilt line "in frame k the X is at lower left" would be false on about 94% of rows. The task is a cross-frame one: the camera pose of frame k against objects remembered from other frames.
- **What build B can state truthfully from the row's own provenance** (`camera_frame`, `first_seen`, `frame_n_share`, `instances` with frame and share, `geometry_values`; left-right rows also carry `frame_n_bearing_deg`): per object one of two lines, chosen by `frame_n_share >= visibility_floor`: "X is in view in frame k" or "X is out of view in frame k; it was seen in frame f"; then the relation stated relative to the frame-k camera. No row holds boxes, masks, depth or a pose matrix for frame k (0 of 30 audited), so an image region at k ("lower left") cannot be rendered from the row; it needs the raster the provenance points to.
- A REMOVE list of rows whose objects are all out of view would drop about half of each family (588 of 1,200). Do not remove them unless the benchmark type excludes such questions; that is not established from dev data, and the dev items carry no visibility field.
- **Shortcuts the rebuild should balance** (dev step 200, recounted): last option chosen on 54 / 64 / 100 of 150 (camera v1 / v2 / v3) against 37 / 50 / 75 truths; Right on 110 of 150 against 79 truths; Up on 92 against 76; Far on 94 against 86. - **The model's order barely moves with k:** over pairs of dev camera items in one room with different k whose true winner changes, the model's top shared object changes on 18 of 59. This is the behaviour a frame-k trace has to change; use it as build B's gate at the next read.
