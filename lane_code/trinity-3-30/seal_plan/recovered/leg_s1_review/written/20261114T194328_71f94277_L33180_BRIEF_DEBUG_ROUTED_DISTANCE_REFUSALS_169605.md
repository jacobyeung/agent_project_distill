# Debugging: the routed read's first real items (Orchard pilot 169605): refused grounding calls, a runaway decode, and a unit error

## Background

We trained a spatial vision-language model ("the leg", run 469ddece; this is its step-200 export). Some question types are answered by the model calling its own heads and perception tools from inside generation; a "routed reader" serves those calls and scores 636 development items (150 object-distance, 36 room-size, 450 camera). Each item is read by two arms that share the same tower geometry, frames, candidate policy and frozen mask proposals: the **unflagged** arm is the model's own natural program; the **scripted** arm is a fixed reference program for the item. The reader's specification is `/scratch/jjyeung/orch_cd/legs1_routed/out2/ROUTED_READ_SPEC_NOMDG.md` (81 lines; read it first). After five failed pilots, pilot 6 passed the parity gate and ran five geometry captures and ten item pairs. This is the first real data from the routed read, and it shows three things I need explained before any full read:

1. **Distance items.** In both distance pairs neither arm produced a recognized answer, and each arm recorded call errors. For `vsi590k_161825` (label 3.34 m) the refrigerator was grounded and the bucket was "refused as outside the fixed candidate universe". For `vsi590k_161841` both the microwave and the printer queries were refused "because the routed policy requires a fixed named candidate universe". The specification says a scripted operand missing from the mask cache becomes an item refusal at admission (`mask_cache_operand_missing`), yet the pilot's mask request reported no operand refusals for these items. So either the admission check and the runtime policy disagree, or the items are answerable and something else refuses them.
2. **A runaway decode.** On the second distance item the model's decode reached `call_limit` after 14,754 generated tokens and took 860 s; the other nine pairs took 4 to 21 s. Projected over 636 items this makes the full read 55 hours and 1.26 GB of return, so the full read's admission refuses. The plain (direct) evaluation of this model uses a 2,048-token thinking budget with a 64-token forced answer.
3. **Room size.** The one room item asks for square feet; the tool returned square metres; the model answered 38.36 (the square-metre value) where the scripted arm answered 412.9 (label 378; scores 0 and 0.9).

The camera items behaved: the first one served `<move from=11 to=28>` and both arms answered 5.61 m against a label of 5.49 m.
