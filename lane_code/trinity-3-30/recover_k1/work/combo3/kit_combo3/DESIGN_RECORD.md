**Question.** Which required objects never enter the mask cache, how much answer accuracy could their recovery restore, and which bounded GPU experiment can test that recovery?

**Answer.** The cache misses 224 of 1,056 operand-instance targets across 93 GT-covered captures. Among those misses, 81 remain unexplained by size, view count or exact naming; 74 have at most two usable views; 23 never reach the executor’s 154-pixel threshold; 22 have no visible GT pixels; 13 have a non-exact annotation match; and 11 have SAM presence below 0.2 in every visible frame. These groups describe measured conditions and do not establish visual causes.

The independent GT grants recover +14.34/+12.31 points for unresolved misses, +8.82/+8.57 for scarce-view misses, and +1.84/+1.10 for presence-censored misses, on absolute distance/counting. Size-threshold and zero-visibility grants recover zero. The effects interact and must not be added as independent benefits.

**Evidence.** NEVER_PROPOSED.md contains the full dataset, category, size, visibility, distance, prompt and occlusion-proxy tables, plus 30 numerical case reads. PER_INSTANCE.jsonl records every target and visible frame. The audit uses the same greedy one-to-one IoU>0.5 rule as the route decomposition. Six separate grant experiments run the frozen programs and route-table pairing; the optimized executor reproduces 6,846 existing GT endpoint predictions and scores exactly. The 28.29/23.19-point reference contrasts use 76/91 GT-covered pairs, not all 150 items of each type.

The annotation matcher incorrectly treats “ceiling light” as “ceiling” through substring fallback. Thirteen targets have that problem: ten in the lexical group and three in the scarce-view group. The lexical group’s entire +1.84-point paired distance gain comes from granting ceiling surfaces to two lamp questions. The ordinary table/desk and counter/kitchen-counter mismatches recover zero on the paired distance/counting sets. The report flags this artifact and retains the original matcher only to reproduce the existing route decomposition. Excluding questions exposed to the suspect mapping leaves never-proposed contrasts of +28.77 points on 73 absolute-distance pairs and +23.79 on 87 counting pairs; the main recall bottleneck persists.

The cache stores all conditional scores but only retained masks. Lowering the joint floor to 0.05 creates additional score-eligible candidates in visible frames of 178 misses, but their overlap is unknowable without new inference. Forty-one misses have at least one cap-clipped visible frame. Twenty-four visible misses have every raw joint score below 0.05, so that dense setting cannot add a proposal there.

The earlier presence evidence is in verify_kit/out/decision589_20261110T1915Z/PRESENCE_REPORT.md, reached through the selector events and run cards. Its held-out-room AUROC is 0.9741 for the student’s P(yes), versus 0.9490 for SAM presence. This is first-token image inference from a base model, not a released lightweight feature probe. The existing PRES32 runner and model backend provide usable code; the delivered wrapper binds them to the current frames and checkpoint.

**Implementation.** The kit adds a frozen density experiment, its zero-inference linker-floor ablation, language-only prompt expansion, targeted tiles and student-triggered tiles. It preserves baseline candidates and source-specific scores when adding prompts or tiles. It verifies the baseline subset of dense inference before admitting that capture. It uses the same frozen selector and program executor for all variants; no model is fitted on these results.

Each variant has a bound manifest, an estimate, append-only capture journals, resume checks, a hard stall watchdog and output/time caps. The student variant first produces bound per-frame presence rows, then seals their hash into its manifest. Its gate triggers searches and never removes baseline proposals. All candidate and presence inference is offline and uses one visible GPU. All pricing, intervals and recall tables run on CPU.

The pricing defect was two NumPy-valued counts in diagnostic_objects. Casting each boolean comparison to a Python integer fixes serialization without changing predictions. The full CPU rerun produced the missing diagnostics and completion receipt. All 19,853 per-item rows are byte-identical to the original; the complete route-table JSON is equal; 484 capture/name diagnostic groups agree with the independent instance audit. The delivered pricing code additionally resumes from per-capture content receipts and pins GT, head and code inputs.

**Options considered.**

- More frames would require matching geometry exports, frame authority and GT rasters. The current linker, heads and programs all bind 32 anchors. A SAM-only 64-frame cache would not support a valid score comparison, so the kit keeps the anchors fixed.
- Tiles increase effective model sampling within a crop while preserving the original frame and geometry. Upscaling an entire low-resolution PNG cannot supply new information.
- Lowering only the cache threshold leaves the linker’s 0.3 conditional-score floor in place. Dense_link05 isolates this second filter and reuses the dense cache.
- A prompt experiment is retained as a control, but the observed lexical distance gain is an annotation-binding artifact. The dictionary never uses “ceiling” as a lamp synonym.
- A hard student rejection gate could discard correct proposals and harm recall. The implemented gate only spends extra inference on baseline-empty frames.
- Counting all non-matching proposals as semantically false would overstate precision failures when annotations are incomplete. Tables explicitly report annotation-relative precision.

**What might fail, and how to notice.** Dense proposals may be wrong shapes or parts; then eligibility rises without instance recall. The linker may reject them; then dense_link05 changes linked recall while dense does not. Prompt variants may introduce false accepts, and tiles may miss instances when another object of the same category already has a proposal. The per-instance matches, selected-mask overlaps and paired scores expose those failures. More proposals can also split counting identities, so counting is priced separately. Student presence may not transfer to dev-S1 or the supplied checkpoint; its gated variant must earn a score gain rather than inherit the earlier AUROC claim. The inherited GT binding defect and incomplete labels limit semantic interpretation of recall and precision. True occlusion cannot be established from these files.

**Tests that settle the choice.** Require dense subset parity, valid cache/frame bindings, complete matched pricing membership and no stub scores. Compare each variant to baseline on identical questions with 10,000 physical-room bootstrap draws. Inspect proposal recall, precision and selector acceptance by dataset. Adopt a proposal variant only after its paired program gain clears zero without an unacceptable loss on another type. A route change additionally requires the interval against direct answering to clear zero. Use the annotation-binding sensitivity outputs to distinguish a genuine proposal gain from a change on invalid GT targets.
