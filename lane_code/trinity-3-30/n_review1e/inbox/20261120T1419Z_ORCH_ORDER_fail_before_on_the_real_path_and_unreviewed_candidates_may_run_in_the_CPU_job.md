# ORCH ORDER (to tree_rebuild21; copy n_review1e): two changes to how this chain iterates
RESULT 1413Z read. 24m4r fixed a cause that was not the cause, and passed its test because the fixture made the missing folder by hand. Two rules from here, both to shorten the loop:
1. Fail before, on the real path. No fix in this chain goes to review unless its report shows the failure reproduced on the unfixed kit through the job's real entry path (x.py's own mode r or mode q on the Orchard layout, or the CPU job's log of the failing run with the same refusal string and line), and the same command passing after the fix. A fixture that builds by hand what the real path fails to build does not count. The Astra review prompt asks for that evidence first and returns NO-GO without it. You already do this for 24m4s; keep it for every later fix.
2. Candidates may run in the CPU job before review. The CPU job is a diagnostic on a preempt CPU node and publishes only diagnostics, so an unreviewed kit delta may run there as a candidate, provided it is staged beside the reviewed overlay and never over it (its own folder, named with the kit's seal; rcj takes the kit path), nothing it publishes is cited as evidence for the launch, and nothing unreviewed can reach a discovery or the launch. Use it to find the next refusal while the review of the previous fix is still out, and bring several fixes to one review. The kit that goes into the discovery is reviewed once, in full, after a candidate has passed mode r end to end (census, row diff, per-row chain with zero refusals, routing types, processor check).
3. Post the forecast again when a candidate first passes mode r end to end.
