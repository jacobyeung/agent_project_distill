## What this is
We train a ~9B spatial VLM that answers from RGB video (32 frames). Its chain of thought (the text before `</think>`) either reasons directly from the frames ("direct" types) or calls heads inside its own checkpoint (`<ground ...>`, `<gap ...>`, `<move ...>` and similar) and answers from the `<tool_response>` they print ("routed" types: absolute distance and the three camera types). For every question type we need to know what goes wrong in the model's traces, how many points each failure costs, and which training-row or trace change would fix it in the next training run (called vehicle N).

Checkpoints:
- **step 544** = the base: the sealed leg (run 469ddece) at its last step, trained on the older trace forms.
- **step 200** = leg R1 (run 673bc60f), 200 steps into a continuation from that base, trained on the rebuilt rows (store v7, trace ruling of 2026-11-15) plus routed rows and feet/inch unit rows.
Dev sets (never official benchmark items): **dev-S1** (VSI-Bench-style questions on training-distribution rooms) and **R0-dev** (ReVSI-style questions; subtype field gives e.g. toward/away, closest/farthest, single/multiple). VSTI relative dev set (900 items, six types). Facing twins (150 "away" and 150 "forward" items).

Scored arm: **B2048** = the think block is force-closed at 2,048 tokens and the answer is then generated; that score is `score`. The full generation without the forced close (ON16k) is `text`/`score_on`.

Already known; do not redo, build on it:

## Your assignment: what the relative-distance order rests on
Background: on every wrong relative-distance item the trace's stated order has the wrong endpoint and the answer follows it (131 of 131); 62 of 131 have the truth at the adjacent rank. The trace locates only the reference object.
Questions:
1. Stability: on the items wrong at both step 544 and step 200 (31 dev-S1, 72 R0-dev), do the two checkpoints pick the same wrong candidate? Same for R1 step 100 against step 200. A stable wrong choice points to a systematic cue; an unstable one to noise.
2. Priors: how often does the model's chosen candidate coincide with (a) the first candidate named in the question, (b) the candidate that is the largest object by a rough class-size prior (use the size training rows' class medians: sample 2,000 rows of `object_size_estimation|r1g|rows_rebuild_d0_v1` by primary key), (c) the candidate whose class co-occurs with the reference class most often as the answer in training rows (sample 3,000 rows of `object_rel_distance|w1g|rows_rebuild_d0_v1` by primary key; for each (reference class, candidate class) pair count how often that candidate is the answer when present)? Score each prior as a predictor of the truth and of the model's answer on the dev items. If (c) predicts the model better than it predicts the truth, the model leans on a memorised class-pair prior.
3. The model's full order against truth: only the endpoint is labelled, so use step 544's stated metre values as a second opinion: rank correlation between step 200's order and step 544's stated distances, on right and on wrong items.
4. Closest against farthest on R0-dev: training rows are all "closest" (0 of 119 sampled rows ask farthest). On farthest items (93), is the last element of the order right as often as the first element is right on closest items? Is the truth's rank distribution symmetric? Does the model ever answer the first element on a farthest question?
5. Duplicate-instance instruction: dev-S1 questions carry a sentence about multiple instances (150 of 150) and R0-dev do not. Quote it. Does the trace ever act on it?
6. What trace change could help without a head? For example a two-candidate comparison line for the top two. Estimate from the rank data how many items a perfect top-2 comparison would fix (truth at rank 2 for closest, rank 3 for farthest), and say what evidence a row would need to carry for that line to be honest under the trace ruling.
