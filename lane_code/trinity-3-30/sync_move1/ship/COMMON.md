## Standing rules (nobody answers questions while you run; decide, record the decision and its reason, continue)
- You run once, on trinity-2-28. Your only writable folder is `$L` (named above). Everything else is READ-ONLY. Inputs copied for you are under `$L/in/` (`in/tools/` = the installed tools, hashes in `in/TOOLS.sha256`).
- No git (except `git init`/commits inside throwaway test repos under `$L/work/tmp_*`), no ssh, no scp, no Slurm, no deletion outside `$L`, no GPU (`CUDA_VISIBLE_DEVICES=""`), no paid model API, no network.
- Searches stay inside `$L`. Never search or list `/home`, `/data*`, `/` or `/scratch` recursively; sweeping searches have crashed nodes.
- Load: other users train on this node's GPUs. Prefix every command that computes with `nice -n 10`; at most 8 cores and 20 GB RAM; keep `$L` under 2 GB. Fixtures only under `$L/work/tmp_*`.
- Python: the tools run under `/usr/bin/python3` (3.6.8) on every node, invoked as `python3 -I -s -B`; stay 3.6-compatible (no walrus, no f-string `=`, no `removeprefix`, no `capture_output`). If a `python3.12` or `python3.11` exists on PATH, run the tests with it too and report both.
- Deliver the changed tools as complete files in `$L/out/tools/`, unified diffs against `in/tools/` in `$L/out/patches/`, tests in `$L/out/tests/` with one command that runs them all, and an owner package (below). Never edit `in/` in place.
- Write `$L/work/STATUS.md` after each task (time from `date -u`). Final report `$L/out/REPORT.md`: first line `VERDICT: <DONE|PARTIAL> <one sentence>`; then what changed and why, test commands with their exact outputs, measured numbers (labelled measured or estimated), what could go wrong and how we would notice, what is not done.
- Owner package in `$L/out/`: `PREIMAGE.sha256` (current hashes of exactly the files you replace, as `tools/<name>` lines; copy them from `in/TOOLS.sha256`), `POSTIMAGE.sha256`, `SHA256SUMS` (every file in `out/` except itself), `install.sh` and `rollback.sh`. `install.sh` runs as `B=<orch_n30 dir> S=<sync state dir> bash -eu install.sh` and refuses unless `hostname -s` is `trinity-3-30` (where the owner installs; the tools dir `B/tools` is on shared NFS, so one install serves every node). It takes `flock -n $S/.sync.lock` (exits 3 with a message if a sync holds it), checks SHA256SUMS and PREIMAGE, backs up the preimage files into `$S/install-backups/<uuid>/preimage.tar` with `PREIMAGE.sha256`, writes each new file to a temporary name inside `B/tools`, syntax-checks it (`bash -n` / `compile`), replaces with `os.replace`/`mv -f` only after all temporaries are ready, then checks POSTIMAGE. Robust mode is ON in production and stays ON; do not refuse because of it. `rollback.sh <backup dir>` restores the preimage under the same lock and checks PREIMAGE. `in/install_tools.py` is the pattern the owner trusts; reuse it, trimmed.
- Do not invent measurements. A number you did not measure or read from a named file is an estimate and says so. Due 60 minutes after you start; if time runs short, finish tasks in order, package what is done and say what is not.
