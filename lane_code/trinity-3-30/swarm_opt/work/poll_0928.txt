1. **LOW — A content rejection by origin strands the kit commit and blocks every later hourly push.**
   - `out/tools/land_kit.py:283-289` commits on local `lane-code` before pushing to origin.
   - If GitHub refuses the content (for example push protection or a server hook), the commit stays local.
   - The hourly then fails `push origin lane-code` every hour (`in/lane_code_sync.sh:158`). Meanwhile it keeps pushing home (`:159`), so the two remotes diverge.
   - The only way out is rewriting unpushed local history, which needs the user. `GIT_OWNER.md:43-44` says only "investigate".

   - Smallest fix: on a push refusal from origin, print a stop-and-ask-the-user notice, and add one line on this case to `GIT_OWNER.md`.
   - Robust fix: build the commit with `git commit-tree` on a temporary index in the audit directory, push `<sha>:refs/heads/lane-code` to origin first, and only then move local `lane-code` forward with `git merge --ff-only <sha>`.
