Run CPU validation from this workspace with `bash scripts/cpu.sh code/dryrun.py` and `bash scripts/cpu.sh code/test_kit.py`. The CPU interpreter is `/scratch/jjyeung/envs/p1cpu/bin/python`. Run `bash scripts/cpu.sh scripts/finalize_v3.py` to rebuild the report and review archive.

`evaluate_v2.py A` prices context, `B` prices views independently, `C` reports camera diagnostics, and `heldout` consumes one held-out look after both training decisions are complete and the held-out label file exists. All Part A and B choices use the 1,012 pinned K1 train distance rows outside withheld rooms. Full 1,037-row statistics are reported beside them and cannot decide bars. The pinned R0, withheld-80, BENCH v2, dev-S1 and K1 held-out lists resolve through the fixed room checker; all six withheld captures are excluded from pose decisions too. The three factor names are `C32_V32_today`, `C64_V32_today`, and `C64_V64_today`, with corresponding `obj` arms only when the box kit freezes a variant. A2 uses `GTmask` as its box-rule label.

`configs/KBOX_WINNING_BOX_RULE.json` pins sb_kbox4's A0 rows, decision and freeze receipts. No object variant is frozen; `fused_path` applies to GT masks only. Pricing uses `today` arms and one added-frame-gain comparison. Every geometry uses own-depth median_ratio, float32 exp(log(scale)), checkpoint gravity and the serving guard. Missing references stay MISSING.

Part C reads staged step-544 records and never substitutes `heads.pose9` for tower poses. Run `bash scripts/cpu.sh scripts/bind_camera.py` to create `inputs/CAMERA_FRAME_JOINS.json`. The builder joins exact scene and ordered source-frame-index fields to existing local A_MANIFEST selections, checks dense anchor equality, and verifies every PNG byte hash under the request's frame root. All 450 items have 32-frame joins; 431 have dense joins. The 19 items in scannet/scene0475_00 and scannet/scene0475_01 lack their g3s64 DENSE.json manifests. The builder records the exact missing paths and skips those items only in dense arms. Real text parity remains a GPU check.

Future GPU entry points are `scripts/run_A.sh`, `run_B.sh`, and `run_C.sh`. They require the orchestrator's code-bound `inbox/GPU_GO.json` and `inbox/SHARED_GPU_RESERVATION.json`. Part C also requires `inbox/DA3_GO.txt` containing a standalone `GO` line; preflight checks it before any capture work. The latter names the single shared ledger, its sha256 and a reservation ID. The ledger lists completed GPU seconds, active reservations, the specification's order, and `next_authorized_part`. Each reservation binds part, card, workspace, code hash, hard seconds and RESERVED status. This workspace writes start/stop receipts; the orchestrator owns the shared ledger. Local admission cannot replace that ledger.

The hard stops are 0.75, 3.0 and 0.75 hours. The runner accepts one 24-GB Ampere-or-newer card, limits allocation to 40 GB, records peak allocation for every capture/pass, and skips units only when their binding and output hashes match DONE.json. Incomplete attempts and HALTED receipts require operator review. No GPU scripts run during the CPU build. Ruling 0749Z allows this kit's 3.6 expected GPU-hours and the room kit's 0.2 to share one card; schedule passes sequentially with their shared-ledger reservations.

`policy.read_r0dev_once` refuses any R0-dev read until `PRIMARY_ARMS.json` is frozen on K1 train, with exactly a baseline and treatment per category and pinned input hashes. It consumes an exclusive receipt before opening data and refuses another look. This kit neither freezes R0-dev arms nor reads R0-dev or official items.

Use the v2 entry points above. The copied builder scripts are not runtime entry points and are excluded from the review archive. Every produced result records its input hashes. The archive contains code, configurations, pinned inputs, CPU evidence and the report; it excludes weights, frames, GPU tensor caches and runtime fixtures.

At N=64 the unchanged selector divides frame counts by 32/31, so these features can exceed 1. Raw depth AbsRel uses unscaled G3T depth. The A0 response comparison re-formats the stored prediction because kbox4 rows contain no response text.

Each launcher freezes `out/tower_frames/parts/<A|B|C|H>/BARS.json` as its first action and records its SHA256 in `FREEZE.json`. A/B/C freeze before preflight and capture output; `scripts/run_H.sh` freezes H before the held-out look. Scoring entry points require that pair and the same code hash; they refuse missing or changed bars and existing per-item files without writing output. A freeze cannot be created after capture or scored output exists.
