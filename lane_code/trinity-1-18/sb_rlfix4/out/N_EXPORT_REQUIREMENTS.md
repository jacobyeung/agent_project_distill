# What the orchestrator must supply before RL can start from an N export

The kit replays and trains only from A4's m200 SFT export. A journal alone cannot unlock an N export: `replay.check_export` authenticates only A4's `EXPORT_PIN.json` (m200, step 200, SFT), `replay.selection` reads only A4's m200 journals, and `serving.require_replay` requires A4's export pin. `n_export_journal` is documentation only (`scripts/make_configs.py:30`); no runtime reads it.

A4's loader refuses both checked N configurations. `scripts/n_export_check.py` finds that A4's `identity()` differs from N's for `sb_f64/pkg/work/build18/inputs/config.json` and `sb_f64/pkg/work/n1fix2/inputs/config.json` (`out/N_EXPORT_CHECK.json`), so `in/claimed_reader/b/e2e_reader/parity.py:144-147` raises `loaded export identity differs`. This check compares identities only; it loads no weights and does not cover every possible N export.

Supply each item below as an exact local `/scratch` path with its SHA256. Do not infer a mapping, substitute another export or relax the identity check.

1. **`n_export_journal`.** The deployed-reader journal of this exact N export, served through the claimed arm (G3T camera and lifting, SAM 3 with `candidates_argmax`, own gravity, own depth for scale). Each complete row must record token IDs, finish reason, call records with families, `decode_budget` including `fired`, item ID and question type, and completed-read status. Its environment must name the export's step and lineage, and its inputs must hash the item manifest, frame manifest and selected frames.
2. **Export identity and restore.** Paths and SHA256 values for the original artifact, heads, full weights and preparation config, plus the authenticated `RESTORE.json` and its local files. They must match the journal's export and the export training loads, since `require_replay` compares the receipt's `export_identity` with the training export.
3. **A compatible sealed loader.** The reader package and loader that produced the journal, with code, settings and arm pins, and a reviewed compatibility path for N's stored identity. Editing A4's identity check without a supported export-loading contract is not a fix.
4. **Replay coverage from that journal.** Four complete items for each of the five supported types, four reads whose calls include at least two grounds and a gap, and two reads whose budget fired. A4's m200 item IDs cannot be assumed to exercise these paths for another export. The journal must also pin the perception bytes (G3T, SAM 3, selector, as A4's `INPUTS.json` does) and the execution card.
5. **Admitted training bindings.** A qualified `pool_config`, an ADMITTED `out/PROMPT_POOL.json` written from it, an artifact binding (`grounding.artifact_manifest`) admitting the immutable export and every frozen perception and code asset, and a GPU PASS replay receipt (`greedy_replay`) bound to those inputs. The `init_m544` entry in `sb_f64/pkg/work/n1fix2/inputs/registry.json` currently has `record: null` and status `overlap_outside_claim_scope`, so it qualifies nothing.

With these inputs, the kit still needs a reviewed code change: an N-export binding (export pin, journal root and required item IDs per group) that `check_export`, `selection` and `require_replay` accept in place of A4's hard-coded m200 constants, plus tests that refuse foreign exports. The reference checks added in sb_rlfix4 apply to whatever `selection()` returns: the replay cache key and `require_replay` compare every result with its current journal reference and journal SHA256. A matching one-H100 GPU replay must then pass before training.

The A4 m200 route needs only items 2 and 5. Its expected locations are listed under `missing_bindings` in `configs/h100_{4,8}.json`: the m200 `RESTORE.json` and `d/p0/config.json` (SHA256 `3b0051c4a9cc661d02019a645165fc3e23d658d2f24a6fd6fd86ec7877ba4fc1`, from EXPORT_PIN `preparation.config`) on orchard-community-4. The restore staged on trinity-1-18 identifies m544, not m200. All production bindings remain MISSING.
