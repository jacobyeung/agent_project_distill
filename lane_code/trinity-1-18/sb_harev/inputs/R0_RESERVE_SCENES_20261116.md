# R0 reserve scenes: rooms no checkpoint of the lineage has seen (brief 10, 2026-11-16)

**Question.** Which captures with ground truth on Trinity lie outside every training stream of the lineage (T0, CP1, LEG-S1, D0) and outside every benchmark and dev room, so that development reads can decide route against direct and RL can draw prompts whose answers the direct path has not memorised?

**Answer.** R0 holds 374 captures in 372 rooms. R0-dev is 100 ScanNet++ rooms with full ground truth (iphone video, laser-scan mesh, instance annotation, aligned poses); it decides route against direct per type and is never trained on, never used for RL and never used to fit prompts or thresholds. R0-rl holds the other 272 rooms (274 captures): 62 ScanNet++ captures and 12 ScanNet captures (10 rooms) with full ground truth, plus 50 ScanNet++ captures with mesh and poses only, 50 with poses only, and 100 ScanNet scans_test captures. ARKitScenes contributes nothing: its 3 clean venues have no data on Trinity. Every later leg excludes every R0 room from every stream (ORCH registered this at 13:06Z).

**Files.** `R0_RESERVE_20261116/R0_SCENES.json` (sha256 f7c45817; per-capture room key, split, GT level, authorities with sha256), `R0_ROOMS.txt` (bdb5d402), `R0_DEV_ROOMS.txt` (855ef477), `R0_REGISTRATION_NOTE.md`. Code and inputs: trinity-1-18 `/scratch/jjyeung/orch_n30/b10_reserve` (`code/census.py` 817fb604, `code/build_r0.py` aaaa3d90, `code/test_exclusion.py` 9f25653f). Questions and frames (in the archive below and on trinity-1-18): `out/qsets/R0_QUESTIONS_{dev,rl}_f{32,64}.jsonl` (dev_f32 b4e278f2, dev_f64 038336db, rl_f32 5c4034f9, rl_f64 0b168fe6), `R0_QUESTIONS_SUMMARY.json` (8444684f), `DEFERRED.json` (cb765f42), `FRAMES_MANIFEST.json` (450e4125; per-scene PNG sha256 manifests), all three copied here; `frames/scannetpp/<scene>/<frame>.png`; code `gen_questions.py` r0gen-v2 efc782a0, `aggregate.py` 257f2c33, `decode_frames.py`, `pose_diag.py` 29b9fa28. **Questions and frames.** Frames follow the trained layout (32 and 64 indices floor(linspace(0, total-1, n)), iphone rgb.mkv decoded with PyAV 15.1.0, bicubic 640x480 PNG): 162 scenes, 15,228 frames; every manifest matches the decoded frame count and the bytes on disk, and a re-decode of two scenes reproduces every PNG hash. Questions use the D0 v5 wording and raw ScanNet++ labels (as the D0 rows do), with answers computed per layout from frame-tied visibility (instance raster from the aligned poses, at least 8 px at 160x120; overlays on three dev scenes line up with the frames). Six scenes fail the pose gate (aligned_pose against iphone colmap, median error under 0.05 m) because their aligned poses are corrupt or drift; they stay in the denominator as deferred (2 dev, 4 rl). The set holds 5,566 items in 156 scenes. R0-dev (98 rooms): counting 385, size 293, absolute distance 290, relative distance 279, appearance order 246, direction easy 192, medium 194, hard 192, room size 98 (one per room). R0-rl: 3,397 items from 58 ScanNet++ scenes; its ScanNet and partial-GT captures have no questions yet. No-information constants on R0-dev (fitted on R0-rl): counting median 2, MRA 62.2 (32 frames) / 60.2 (64); absolute distance 1.885 m, MRA 29.5; size MRA 18.3; room size MRA 33.1; direction easy, medium and hard top option 51.6, 35.6 and 30.7 against chance 50, 33 and 25; answer letters near uniform. Checks over every item: relative-distance gaps at least 0.20 m, direction angles at least 15 degrees from a boundary, appearance answers equal to the first-seen order, 0 inconsistent answers.

**Evidence.** The census builds the universe from directory listings of ScanNet scans and scans_test (1,613 captures, 807 rooms), ScanNet++ (1,001 scenes) and the ARKitScenes 3DOD metadata (5,047 videos, 1,669 venues). It removes every capture whose room appears in division A3 (f41d15aa, train and held-out), the kit07 frame map (17aa3e9e) and frame rates (36ae882f), the D0 v5 VQA scenes, the LEG-S1 MDG raster scenes, BENCH v2 (3119aa4a: VSI-Bench, ReVSI v1, VSTI and the rest), the exclusion lists 99e6eed6, 932c0c4e, dafa4a9c and 600ef69d, dev-S1 (969cdb56) and WITHHELD_ROOMS_80 (634820b4). Keys resolve through the native id and the rung1, rung2, v590kgt and posedata token families; every authority resolves with 0 unresolved keys. An independent test searches each authority's full text for each R0 capture's native id, room id and alias tokens and finds none; a mutation check shows the same search catches trained and benchmark captures. R0 shares no scene with rows_a2's 686 A2 scenes.

**Split.** Rooms with full ground truth from ScanNet++ are ordered by sha256('R0 split v1 ' + room); the first 100 form R0-dev. Keeping dev on one ground-truth source avoids decoding ScanNet .sens files (about 25 GB) for development reads.

**Options rejected.** ARKitScenes 3DOD Training (2,899 captures): every local capture is trained or in a benchmark venue. ScanNet scans_test as dev rooms: no instance annotation, so only room size and pose questions. A dev split mixing ScanNet and ScanNet++: five ScanNet dev rooms would have required the .sens stream before any dev read.

**What might not work, and how we notice.** (1) Separate T0 and CP1 stream scene lists were not found; the census assumes the kit07 frame map and division A3 cover them. The refute review (Codex gpt-6-astra, 13:20Z) found no collision but rates this unproven; a found list is re-run through `test_exclusion.py`. (2) ScanNet++ has no cross-scene physical-room key, so an R0 scene could be a recapture of a trained room; nearly identical meshes would show it. (3) The base model's pretraining exposure is unknowable. (4a) BENCH v2 records 134 MMSI-Video clips without scene mappings, so their rooms cannot be excluded by key. (4) R0-rl is small for RL (74 full-GT rooms); prompts per room, not rooms, set the RL pool size.

**Tests that would settle it.** The T0 and CP1 stream scene lists, run through `test_exclusion.py`; scene mappings for the 134 MMSI-Video clips; a mesh-similarity scan of R0 ScanNet++ scenes against trained ScanNet++ scenes.
