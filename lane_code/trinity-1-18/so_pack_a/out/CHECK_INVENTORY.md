## Scope of the wrapper and source-regression evidence

`pack.py check` invokes `logic`, `guard`, `trap`, `stop`, `login`, `fill` and `receipt` on the built package, then validates every generated phase script. The source release harnesses `check_release_d.py` and `run_release_gates.py` are not launched by that per-delivery command. Their built-byte hash, bundle, sequence, memory, input-selection, return/stop and CPU-receipt predicates are covered by the corresponding probes; no claim is made that the original routed release-suite harness itself ran here. The standalone `test_native.py` executes the exact D checker with its workspace redirected under this task directory.

The raw supplied D source tree fails `check_release_d.py` because `score_d.py` differs from the copy embedded in `o_build_D.sh`. The additive token adapter preserves that same failure. A separately labelled coherent snapshot of the authenticated embedded assets passes the unchanged checker before and after adding the adapter. Thus raw-source release consistency remains a production prerequisite. The tests do not claim that a synthetic export is the same input as a production export; production preflight requires authenticated mirrors of all actual bytes and fails when they are unavailable.
