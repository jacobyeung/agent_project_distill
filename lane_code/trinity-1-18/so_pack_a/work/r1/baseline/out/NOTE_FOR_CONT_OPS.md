# Step-600 packaging

`pack.py` calls the existing r10 or D builder, checks the resulting bytes on Trinity, and prints exact throttled, timeout-bounded ossh commands. Every action defaults OFF; pass `--enable`. Nothing here is armed or submitted.

1. Copy the required native build inputs into a new local workspace. Pin the builder, every input and CPU/GPU script by SHA256 in the configuration. Provide a current read-only Trinity token ledger. For r10, KROOT must contain the original authenticated A/B deliveries and old A filled/base input files; the supplied mirror does not contain those original delivery archives. For D, use the actual items, binding and timing inputs. Use `pack_token.py --kind d|r10 --source ... --enable-token --token {token} -- ...` as the configured builder. The adapter calls native builder code and changes only the token mint when explicitly enabled.
2. Supply step-600 export/preparation pins and local mirrors for every remote part, dependency archive, template group and bwrap file. Each mirror has `path`, `bytes` and `sha256`; remote names remain unchanged during the isolated dry fill. Set `max_read_bytes` to an explicitly authorized budget. The default is 1 GiB, so large inputs fail before unapproved reads. Obtain permission under the cluster IO rules before copying or checking large shared-storage inputs. Do not use fixture pins for a release.
3. Set `normalize_wrapper: true` explicitly for r10/D batch wrappers. The native trap invokes `head`, which conflicts with the adopted literal argv substring rule. This switch changes only that invocation to `sed -n '1p'`, adds `umask 077` after Slurm directives, and reseals the manifest. Default OFF preserves the native delivery bytes. Source comments, stdin bodies and nested archive contents are not name-list surfaces; job comments, argv, environment values, workdirs and created paths are.
4. Run `python -I -s -B pack.py build --enable --config CONFIG --token HEX`, then `check --enable --config CONFIG`. The check runs real login Python 3.6.8 place/fill/3.py paths, imports under isolation, nonzero frame-row checks, native planning/guard/receipt predicates, archive resolution, EXIT capture and USR1 tests. It also seals and checks all remote phase scripts before placement. A missing mirror, stale source hash, D embedded/source mismatch or changed package fails closed.
5. `place` and `fill` print commands; `submit` additionally requires `--yes --token HEX`. `all --enable --config CONFIG --yes --token HEX` builds, checks and plans everything first. Add `--execute-remote` only in an authorized operational session. CPU submit returns promptly; Trinity polls at least 60 seconds apart. Every remote call has a maximum 300-second timeout and its stdin is throttled to 8,000,000 bytes/s. Three consecutive accounting errors stop polling; a transport failure stops immediately. Attempt markers forbid automatic retries after remote side effects.

The example schema is `config_step600.example.json`; placeholders deliberately fail until replaced with reviewed paths and hashes. Local logs and BUILD/CHECK JSON files bind the delivery, exact tested file tree, configuration and checker source. Preserve them with the patch/source manifest. Refresh the ledger before each new build; Orchard also rejects an existing token directory atomically.

The absent routed release-harness tests and production full-reader inputs remain unverified; complete those checks before treating a release as ready. This tool does not establish real GPU behavior, production memory, scheduler signal delivery, trainer-rank USR1 handling, queue priority or step-600 export availability. B4's unknown early-failure cause remains unknown; the trap makes a repeat readable. Native D reports a 19,595-second read budget and `budget_fits=false` for its four-hour fixture; the tool preserves that native result. The supplied D tree also contains a pre-existing scorer/embedded-script mismatch: run the native source generator in a reviewed workspace to create a coherent release before relying on `check_release_d.py`. Patch 02 adds files and does not alter that scorer or any native builder.
