Failure mechanism

Capture 1 commits successfully in PROGRESS.jsonl. Capture 2 saves its G3T output
and then fails in SAM encode at vitdet.py:247, abs_pos[:, :1]. Sam3Tower.encode
runs _load under torch.inference_mode(), so model construction produces inference
parameters. GPU.tower offloads SAM and GPU.sam reloads it outside that context.
PyTorch's Module._apply replaces each Parameter's data on a real device copy.
This mixes normal tensor data with an inference-created Parameter whose version
counter remains disabled; the next inference-mode slice raises the observed error.

The reproduction uses the real GPU.tower/GPU.sam methods, Sam3Tower._load,
encode, and SAM's actual get_abs_pos function. It replaces heavyweight SAM
construction/assets and the image backbone with a parameterized CPU fixture.
Its device-move stand-in calls Module._apply with Tensor.to('cpu', copy=True),
preserving dtype, values and Parameter identity while forcing real data replacement.
A plain .to('cpu') would be a no-op and would not test this mechanism.
