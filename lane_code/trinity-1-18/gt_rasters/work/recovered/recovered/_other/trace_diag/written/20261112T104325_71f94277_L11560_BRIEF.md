## Why
We train a 9B vision-language student for spatial questions about indoor video. Its current best checkpoint ("CP1 m200") scores 71.6 on our held-out development set and 58.6 on the ReVSI benchmark, where frontier closed models score 87 to 90. We need to know, per question type, what kind of error costs the points, because each kind has a different fix (more or different training rows, a change to the short "program" the model writes, a perception head, or an answer-format rule). Two failure kinds were found by hand today: direction questions asked while facing away from the reference object (the model ignores the reversal; 14% against 91% on the same scenes facing toward), and counting questions that ask for a total (it answers a sentence with separate counts). Find the rest, with counts.

## Do
1. For every question type on each set, split the errors into named causes with counts, on ALL items where a rule can decide and on a hash-chosen sample of at least 40 failures per type read one by one where it cannot (fewer if the type has fewer): wrong or missing object in the stated grounding; stated positions, sizes or distances far from ground truth (where the pricing files give it: quantify the error of the numbers the model states); correct numbers but wrong arithmetic or rule; wrong reading of the question (facing direction, "total", units, which object is the reference); answer format the scorer cannot parse; thinking that runs to the cap; label looks wrong or ambiguous; other. One example quoted per cause.
2. For numeric types give the error distribution of the final answers (ratio to the label: median, quartiles, share within 10% and 25%) and, where the reasoning states intermediate quantities, of those too: does the error come from perception (the stated numbers) or from the step after it?
3. Route planning (29 on the development set, 35 to 44 on ReVSI): what does the model do: does it reason about a path at all, guess, or copy a pattern; which turn positions fail; does it fail more on longer routes.
4. Counting below the constant answer: is it miscounting, a constant habit of its own, double counting across frames, or the question form.
5. For each cause, the fix class (training rows of a stated kind; a program or runtime change; a perception head; an answer-format rule; nothing: label noise), and the points it would recover on that type and overall on each set if fixed completely (an upper bound from the counts). Rank the causes by overall points.
6. Compare the three ReVSI runs on the same items: which items does the thinking-off run get right that the thinking-on run gets wrong, and the reverse, per type; what does that say about when thinking helps.
