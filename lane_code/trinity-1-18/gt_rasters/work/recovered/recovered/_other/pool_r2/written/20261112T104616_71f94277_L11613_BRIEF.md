## Why
Our next training run ("LEG-S1") trains a 9B spatial student on five streams; its "routing" stream is materialized from a pinned pool of rows (the model's reasoning as short programs, or direct answers). Two reviewed additions could not enter this run because the tree has no way to add a row set with a chosen share without code changes: its lane wrote that a quarter share "requires a bound source-mixture or sub-selection contract in materialization, sampling and resume identity" (/scratch/jjyeung/orch_cd/leg_s1_tree/events/20261112T0930Z_NOTE_tree_frozen.md, the two "Facing-away" lines). The next run or the next 24-hour leg must be able to take such sets the hour they are reviewed. Build that now, and build one more row set whose need was measured today.

- Base: the newest sealed tree archive named in the newest /scratch/jjyeung/orch_cd/leg_s1_tree/events/*_NOTE_tree_frozen.md (extract it into work/; the lane's out/REVIEW_RESPONSE.md, STATUS.md and its kit builder describe materialization, the pool selector, the per-step recipe of 320 rows and the resume binding).
