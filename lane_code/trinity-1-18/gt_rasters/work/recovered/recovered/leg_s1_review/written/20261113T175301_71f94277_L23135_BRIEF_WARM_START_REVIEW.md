# Independent review: a private patch that warm-starts a training run from a weight export

You are an independent reviewer from a different model family than the author. Be exact; a silent error here would corrupt several hundred GPU-hours of training without any crash.

## Context

A 1,000-step training leg of a 9B vision-language model runs in 24-hour allocations. Between allocations its full state (FP32 master weights, optimizer state, per-rank random state) is meant to be carried in a "slot" on a shared filesystem. That filesystem may be full when the first allocation ends. Then the only surviving state is a milestone weight export: BF16 weights and heads plus `artifact.json`, with no optimizer state. The contingency is a NEW run that initializes from that export and continues the absolute step counter, the learning-rate schedule and the sampler's row plan from the export's step, with a fresh AdamW. The sealed source supports initialization from a milestone but not absolute-step continuation, so the author wrote a private patch. Nothing is sealed or released; this review decides whether the patch is fit to seal if the contingency is needed.
