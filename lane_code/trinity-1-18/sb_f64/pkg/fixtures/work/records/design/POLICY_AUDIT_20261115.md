## Question
Which free choices in the routed reading path were made by looking at benchmark items, for the recorded official VSI-Bench read and for the planned native reads of the step-544 model? How large could the resulting bias be, what can be said about 65.14 / 65.4 today, and how can these choices be re-frozen cleanly?

## Answer
- **Seven choices were selected on VSI-Bench ScanNet items (VSI-Sc):** the route table (#1–#3, and through it the room route the native model carries in its data, #5), the fusion box rule (#6, 25 candidates), the room rule (#7, 5 candidates), the depth cut (#8), the depth source (#9) and the fallback rule (#16, chosen after benchmark results were read). The same work also selected the fusion box rule on all 5,736 VSTI items. The ScanNet scenes overlap ReVSI (73 rooms), so every VSI-Sc selection is also a selection on ReVSI scenes.
- **dev data later confirmed most of them before the official read**: abs route (dev-S1), box rule for abs (dev-858), depth cut for abs (dev-858) and depth source for abs (dev-S1). **dev data did not confirm the room route** (dev-S1: +6.7 [−14.4, +25.0] on 36 items in 9 rooms, undecided), and no clean data chose among the five room rules.
- **The proposal setting (#11), the gap rule (#10), the budget (#18), the frame layout (#19) and the VSTI camera route (#4) are clean.** The selector (#13) is clean for VSI-Bench but was fitted on 44 VSTI rooms and 18 ReVSI rooms.
- **The bias on 65.14 is bounded by about 0.4 points, and it sits in the room route.** Dropping the room route, as the clean dev-S1 rule requires, gives **64.76 strict, +0.96 [+0.47, +1.45]**, and 64.97 with fallback, +1.18 [+0.73, +1.63]. Off the selection scenes the room program loses to direct: ARKitScenes 59.67 against 62.33, while ScanNet++ gains 66.4 against 61.8 on only 50 items. On ScanNet, the selection scenes, it wins 78.07 against 66.14.
- **The abs route does not shrink off the selection scenes.** With fallback, ARKitScenes gains +11.7 and ScanNet++ +6.3, against +9.5 on ScanNet. Strict, ScanNet++ gains only +1.1, which is a proposal-recall effect (24 of 210 items have no answer), not a fusion effect.

- **Fallback (#16).** Choosing fallback over strict adds +0.22 at the frozen setting and +0.67 at baseline proposals. Quoting 65.4 means taking the best of four arms read on the benchmark (65.43).

## What the recorded result supports today
- **Clean in it:** the proposal setting, the selector for VSI-Bench, the gap rule, the frames and the f17 direct arm as a fixed reference. The abs route, the abs box rule and the depth source were selected on VSI-Sc but confirmed on clean dev data before the read.
- **Not clean in it:** the room route and the room rule, both chosen only on VSI-Sc. The fallback rule and the 65.4 figure come from post-read arm selection.
- **Defensible statement:** "An external program route for absolute distance around f17, with a route, fusion rule and depth source that development scenes confirmed, scores 64.76 on official VSI-Bench against 63.79 direct (+0.96 [+0.47, +1.45], strict, rule fixed before the read). Adding room size, whose route rests only on VSI-Bench ScanNet items, gives the pre-registered 65.14 (+1.35 [+0.57, +2.13]). Off its selection scenes the room route gives no measurable gain." Report 65.4 only as a post-hoc arm. All of these are external diagnostics, not learned end-to-end results.

## Re-freeze plan (no official native read may use a benchmark-chosen rule)
Ground rule: K1 captures are training-corpus rooms. The student saw them, so its direct answers there are inflated. Use K1 only for **program-side** choices, where no model answer enters: fusion rules, depth cut, depth source, room rule and the selector refit. Decide **route-or-direct** only on held-out dev-S1, which is disjoint from all seven benchmarks. Pre-register one dated file with every rule below before any K1 GPU output exists, as `K1_RULES.json` already does for the selector.

1. **Now, CPU: pre-register `ROUTED_PATH_REFREEZE_PREREG_<date>.md`.**
   - Per type, the candidate set: the 25 box rules, 5 room rules and the depth-cut grid (P10/P90 margins {0.05, 0.10, 0.15, 0.25} m × erosion {1, 3} px), plus depth source {G3T, V-C}.
   - The rule: keep the frozen choice unless a challenger beats it on K1 train rooms with a paired room-bootstrap lower bound above zero **and** holds the sign on K1 held-out rooms. Ties go to the frozen choice.
   - Route table rule: route a type only when the dev-S1 paired interval lies above zero, using the step-544 checkpoint's own direct answers and the refitted selector.
   - Fallback: one declared primary arm (strict or fallback, chosen now) and the other as secondary, for every native read.
   - The guard threshold (#21), fixed from dev-S1 and training GT only. The official raw-G3T proxy stays a pricing tool and never sets the threshold.
2. **Close the K1 heavy-IO question**: dense RGB for 153 captures (`b6_build/out/HEAVY_IO_QUESTION.md`). It is the user's call.
3. **K1 GPU pass (3.1 to 3.5 GPU-h)**, then the selector refit (#13) under `K1_RULES.json`.
   - Extend the same tables with GT-mask and selector-mask arms for the pre-registered fusion, room, depth-cut and depth-source candidates (CPU).
   - K1 has only 51 ScanNet captures. A VSTI-legal choice of the camera-object rules needs about 300 ScanNet *train* scenes (`gt_ceiling/events/20261111T1752Z…:8-13`). Until those exist, keep camera-object types direct on VSTI.
4. **dev-S1 (held-out):** re-price the route table with the refitted selector and the re-selected rules, on the step-544 export. Apply the step-1 route rule. Room routes only if its interval clears zero. dev-S1 room has only 36 items in 9 rooms, so add the dev-S1 withhold rooms' room items if GT exists, or keep room direct.
5. **Freeze** one dated file listing every value in the inventory table with its clean evidence. It supersedes the fusion, proposal and route files for all reads after it.
6. **Native official reads only after step 5**, in the order VSI-Bench, ReVSI, VSTI.
   - ReVSI and VSTI mask reads are allowed only with the refitted selector.
   - VSTI routes camera types only, unless step 3's ScanNet-train freeze exists.
   - Re-score the recorded external VSI read under the re-frozen rules on CPU from the cached candidates, and report it beside 65.14.
