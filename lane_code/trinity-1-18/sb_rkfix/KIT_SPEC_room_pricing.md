# Room-call pricing specification

The executable protocol is OPERATOR.md. The binding 0607Z ruling gives R0-dev one comparison per category. K1 training captures choose every arm, threshold and frame budget before that comparison. Official benchmark items are never read.

1. Freeze R1 step 200, read 0, journal 4/0, baseline SHA256 `c9b5994cc461420a0ccfb035cd252e27bac6da3016ab5d5a28f77a14239b319d`. The unrounded direct score is 62.75510204081633 and the bar is 67.75510204081633. Neither the baseline nor the bar can change after registration.
2. R0-dev receives only the K1-selected DA3 arm under R0, against direct. T10, an additional u94 comparison, and Part B are never priced on R0-dev. The sole permitted use of u94 is as the single arm if S1c selects it before the read; f32 then receives no R0-dev look. PASS/FAIL evaluates the complete measurement pipeline against the original R0 mesh labels, not geometry quality alone. The sensor-depth label audit is **proposed, unbuilt**; it cannot calibrate or reopen these rooms.
3. K1 held-out, R0-dev, dev-S1 and official benchmark items select no rule, threshold, frame budget, admission policy or checkpoint. dev-S1 is diagnostic only. A trained-route claim needs a fresh unexposed set. Tower pretraining overlap is unknown.
4. Require VERIFIED evidence of K1-train-only kernel selection, its relation to the benchmark-selected rule, and authenticated step-200 reader/checkpoint/frame receipts. MISSING evidence blocks GPU execution; this kit does not invent provenance.
5. S0 verifies full digests and pins exact frame manifests. Every generated JSON records its input hashes. S0 includes its own script hash. Raw supplied evidence keeps its original bytes.
6. S1c runs DA3 on the 32 anchors alone for all 110 K1-train room captures and prices these predictions and the stored dense-64 predictions through the same converter and deployed kernel as reproduce.py. Preregister: “The R0-dev arm is da3_f32 unless the K1 dense-64 input beats it on K1 train with a paired 95% lower bound above 0; then it is da3_u94.” Use the K1 reproduction's room-paired bootstrap, 10,000 draws, seed 20261119. SELECTION.json contains all rows, hashes, interval and choice. The runner refuses R0-dev without a valid selection.
7. Completed predictions resume only with identical prediction/frame/slot/model/weight/code/settings hashes. Host, card and run are provenance fields, not prediction identity. STARTED-only folders are interrupted and require explicit manual COST.json closure before recomputation. Partial predictions, corrupt receipts and stale bindings stop execution. GO binds the current host, physical card and unique run; torch's bare UUID receives the GPU- prefix before comparison.
8. price.py is the only R0-dev scoring entry point. It exclusively creates DECISION_REGISTRATION.json with bar, selected arm, R0, decision rule and code digest before conversion or scoring. It refuses an existing registration, ROOM_PRED.jsonl or PRICING_TABLE.json. A failed scoring attempt consumes the look. PASS requires MRA at least the bar and paired 95% lower bound above zero; NEAR reaches the bar without a positive bound; otherwise FAIL. No T10, additional u94 or Part B comparison is allowed. The scorer CLI rejects --pred.
9. The selected-arm comparison uses 10,000 room-paired bootstrap draws with seed 17. Missing items, duplicates and invalid scores are fatal. No power probabilities are asserted. dev-S1 has only its frozen direct diagnostic block in the pricing table.
10. Budget approximately 0.09 GPU-hours for S1c plus 0.09 for an f32 R0-dev pass on one 48 GB card. These are estimates, not measured runs. If K1 selects u94, allow approximately 0.46 GPU-hours for its R0-dev pass within the same cumulative 1.5 GPU-hour cap. Count loads, captures and authorized retries. OOM drops the selected arm and stops pricing; it never authorizes a fallback or lower resolution. T10, an additional u94 pass and Part B have zero authorized R0-dev cost.

The fixed protocol uses DA3, 504 px, saddle_balanced, seed 0, bf16 on CUDA and native metric scale 1. f32 reads the item's 32 frames. If selected, u94 reads the pinned union and retains those same 32 anchors for pricing. Labels enter scoring only. The CPU S1c fallback runs one eight-thread worker under a 39 GiB address-space cap; it does not fit the present two-hour limit.
