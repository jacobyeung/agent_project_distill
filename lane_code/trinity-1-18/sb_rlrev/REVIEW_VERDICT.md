# sb_rlkit review verdict: GO AFTER FIXES (5 blockers, 7 minor)

The GRPO math, token masking, room gate and CPU proof are sound, and I reproduced each of them. The production rollout crashes on its first draw, and the reward pays answer formats that the official scorer marks wrong. Launch also waits on N's own MISSING inputs (`init_m544` evidence, admitted pool, export pins), which no kit fix supplies. Evidence scripts and outputs are in `runs/`. Tested edits are in `runs/PATCH_{reward,rollout,test_kit}.diff`, with patched copies in `runs/patched/` and `runs/patched_tests/`.

## Blockers
1. **The rollout crashes on its first draw.** `rollout.py:23-24` passes `trace_program_version=` to `carrier_c1_decode.generate`, whose signature (`carrier_c1_decode.py:454-455`) has no such keyword, so the call raises `TypeError` (`runs/patched_signatures2.py`). N's evaluator selects 3.14 through the model and backend alone (`evalpath/run.py:350-357`). Edit: delete the keyword (`PATCH_rollout.diff`). The patched call binds.
2. **The reward scorer fails parity with N's official per-item scorer.** `reward.py:37-40` uses the strict diagnostic parser `parse_answer_v1` and picks the answer type from whether options are present. The official scorer, `evalpath/run.py:70-80` (`score_item`), uses fuzzy first-token extraction and infers the type from the question type. On 74 answer formats, 32 differ (`runs/parity.out`). In 28 of them the kit pays 1.0 where the official scorer pays 0 (`about 12.19`, `12.19m`, `**B**`, `The answer is B`, `(B)`). In 4 of them the kit pays 0 where the official scorer pays 1 (`b`; a choice type stored without options). RL would learn formats the benchmark scores as wrong. Edit: compute correctness with `score_item` (`PATCH_reward.diff`), and give `test_choice_exact` a choice type (`PATCH_test_kit.diff`), because it now scores a choice answer under numeric `room_size_estimation`. After the patch, parity is 0/74 mismatches and tests pass 20/20.
3. **A fake early `</think>` evades the length penalty.** Length is measured up to the first `</think>` (`reward.py:34`), but the official scorer reads the answer after the last one. A 1,500-token thought placed behind a fake early close earns short = 1 and total 1.2 (`runs/double_think.py`). Edit: `if text.count('</think>') != 1: short = route = 0.0` (in `PATCH_reward.diff`). The fake now scores 1.0, below the honest 1.1.
4. **The rollout reads camera pose from a different source than N's routed reader.** The kit decodes with `pose_source='tower'`, which overrides pose with frozen G3T output (`rollout.py:23`, `train.py:82-84,110-111`). N's evaluator calls `generate` with the default `pose_source='own'`, the student's own pose head (`evalpath/run.py:355`, `runtime.py:152-165`, `carrier_c1_decode.py:143-170`). RL would then optimize against camera responses the benchmark reader never prints. Edit: default to `pose_source='own'` and drop `tower_state`, `tower_batch`, `prepare_tower` and `attach_tower`, or record an orchestrator ruling that the deployed reader is `tower`.
5. **One bad draw aborts the whole run and loses everything.** Sampled calls raise `RowRefusal` when a call runs past `max_call_tokens`, past 40 calls (the evaluator allows 200), or past the token budget (`carrier_c1_batch_decode.py:133-155`). `tower_item` catches only `TowerError` (`tower_errors.py:29-34`), and `train.py:117-119` catches nothing, raising even on `tower_error`. Adapters are saved only after step 200 (`train.py:135-140`). Edit:
   - Wrap `sample` in `try/except RowRefusal`, and score a refused or tower-error draw as reward 0 with no backward pass.
   - Replace DDP and `no_sync` with zero-initialized gradients plus `torch.distributed.all_reduce(p.grad); p.grad /= world` after each step, so a skipped draw cannot hang the collective.
   - Save adapters and optimizer state every 25 steps and log refusal counts.

## Minor
6. **Std-normalized advantages amplify format-only gaps.** `train.py:121` normalizes by each group's std (`grpo_math.py:57-66`). An all-wrong group at [0.2, 0.1, 0.1, 0.1] gets advantages [+1.73, -0.58, -0.58, -0.58], identical to a correctness gap of [1.2, 0.2, 0.2, 0.2] (`runs/grpo_check.out`). The CPU proof's 0.1-versus-0 group already gets ±1.0. Wrong answers still earn 0.1-0.2 for format, and a call the answer ignores still earns full route credit (`runs/gaming.out`). Edit: `group_advantages(..., scale_std=False)` at `train.py:121` and `cpu_proof.py:82`, or zero `short` and `route` when correctness is 0. The README's claim that the auxiliary weights stay small holds for raw reward only, not after normalization.
7. **Routed types do not require exact call placement.** The routed check accepts any superset of the required call kinds (`reward.py:65`), so an extra `<pose>` call keeps route = 1. Edit: require exact kinds, with `{'ground','gap'}` for distance (in `PATCH_reward.diff`).
8. **The room gate passes, but the tests skip production code.** I fed every pinned-list member through the production `pool.RoomGate` and none was admitted (`runs/gate_check.out`): K1 held-out 53, R0-dev 100, R0-rl 274, reserve 372, withheld-80 aliases 720, dev-S1 2,084, BENCH v2 2,424. All 233 K1-train controls were admitted, with 0 physical-room overlaps. No pool exists to recompute (`PROMPT_POOL.json` is MISSING). The kit's tests use a local copy of the gate (`test_kit.py:87-95`), leaving dev-S1, BENCH and REMOVE checks untested. The kit also refuses the 272-room R0-rl reserve, which is stricter than the rule; confirm that is intended. Edit: add `gate_check`, `parity` and signature checks as tests.
9. **Pool rows keep ground-truth copies.** The pool uses a deny-list (`pool.py:39-43`), so rows keep `gt_answer`, `source_gt_answer`, `answer_content` and `tool_output_spans`. I found no consumer that leaks them: the prompt is cut at the label start (`carrier_c1_canary.py:21-29`), and the backend reads only phrases with the checkpoint's own MDG (`s1_grounding.py:56-80`). Use an allow-list.
10. **GRPO math, masking and the CPU proof check out.** The proof reruns bit-identically (losses, gradient L1 8372.22, ratio error 0.0228, 14.63 GiB, 118 s; `runs/cpu_proof/`). The kit's 20 tests pass on rerun. Log-prob alignment error is 0.0, and only sampled tokens carry gradient; response tokens condition later tokens without being trained. k3 is ≥ 0 and pulls toward the reference, PPO clipping is correct, and each sequence weighs 1/32. N's package matches its sealed tar (879/879 files), and the kit tar sha256 `eafa9841…` checks.
11. **The GPU estimate is assumed, not measured.** Its arithmetic reproduces (102.1 / 111.0 GPU-h; 459 / 250 s per step), but every rate is assumed: b09's dry-run card only proposes measuring. The real prompt is about 4.2-4.8k tokens against the 4,096 assumed. Draws decode serially although N batches rows. Policy forward plus backward is costed like a single forward. The CPU environment lacks the DeltaNet fast kernels (`runs/cpu_proof/run.log`). Require a timed 2-step, 1-GPU dry run before reserving GPUs.
12. **Some report claims are not backed by files.**
    - `RL_ON_N_REPORT.md:61` calls `in/b09_out/HASHES.txt` MISSING; it exists, and `INPUT_AUDIT.json` lists only RUN.md and STATUS.md.
    - "Correctness imports N's official scorer" and "the decoder handles v3.14" are contradicted by findings 2 and 1.
    - The K1/R0 test claim rests on the test copy of the gate.
    - The config's `grpo.norm` is ignored by `loss.Objective`, which always takes sequence means.
