## Rules for the build (bind every step)
- Write only inside `$L`. Never write on /home or /data*. Read only files this prompt names there; never list, search or grep on /home or /data*. Search inside `$L` freely.
- No deletion commands and no names of deletion operations in shell text. Write scripts and tests into files and run them by path. No tmux, ssh, GPU, Git, network or another agent.
- Never copy a checkpoint, frame set, database or cache. Never materialize a full store on this node: slices of at most 2,000 rows per family. All temporary files go under `$L/work/tmp`, with `TMPDIR` set to it; the test harness sizes that folder before and after every test and refuses above 200 MB. Run tests under `ulimit -f 204800`. Check `df -BG --output=avail /scratch` before any write over 50 MB; stop writing below 85 GiB free. The lane holds at most 2 GB in total.
- Python: `/scratch/jjyeung/envs/p1cpu/bin/python -I -s -B` (Python 3.12, torch 2.11 CPU, transformers 5.12), at most 8 threads (`OMP_NUM_THREADS=8 MKL_NUM_THREADS=8`), `CUDA_VISIBLE_DEVICES=""`, `PYTHONDONTWRITEBYTECODE=1`. The `coverage` package is absent: measure changed-statement coverage with the standard library (`trace` or `sys.monitoring`) and a small script you write.
- The model answers from RGB end to end; its heads and frozen towers run inside its forward pass; numbers reach the language model as text tokens. A training trace is never answer-only and never states a quantity that the frames, a printed tool response or explicit arithmetic in the trace does not supply. Frames are named by number, never by seconds. No benchmark answer or statistic of benchmark answers chooses a quantity, quota or threshold. Every sealed scene exclusion stays (benchmark scenes, held-out dev-S1); unknown overlap is not a pass. Geometry is reconstructed from dense frames, then subsampled.
- Every number in a report carries its source path; guesses are labelled GUESS. Say what you did not check.
- A CPU proof runs the real producer and reader functions end to end, with stand-ins only at the GPU boundary (say exactly what stands in), and records changed-statement coverage.
- Report: keep `$L/work/build1/STATUS.md` current after each step; at the end write `$L/out/BUILD1_REPORT.md` and append a section "Build 1" to the design record `$L/out/DESIGN_RECORD_tree_rebuild_20261115.md` (create it if absent: question, answer, reasons with evidence, options rejected and why, what might not work and how we notice, tests that would settle it, status).
