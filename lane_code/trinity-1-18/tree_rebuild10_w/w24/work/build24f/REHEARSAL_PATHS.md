Run `bash work/build24f/go_rehearsal.sh` from outside the Codex sandbox. The script uses nice 10, OMP/MKL/OpenBLAS limits of 8, four CPU/gloo ranks, two Torch threads per rank, and a 19 GB aggregate RSS guard. It writes only under this workspace. The prepared synthetic canary is reusable when PREPARED.json authenticates the current tree; an incomplete run refuses rather than overwriting evidence.

The production kits stay unchanged. REHEARSAL_OVERRIDES.json lists the scheduling, resource and transport overrides. FIXTURE_DIFF.json lists every input-config field that differs from kit n. The fixture retains native synthetic databases without copying them. Its model constructor, processor, RGB/labels and frame host are stand-ins. Its host and review receipts authorize this fixture only.

The driver runs the real a.py canary, d.py, h.py, t.py, u.py and train(). The native admission checks see the authenticated fixture recipe. Only run_steps() receives an effective schedule with milestones [2], a one-second checkpoint interval and phase horizons 3/1000/5. Config bytes, admission, trained-group publication and export contents do not receive those loop overrides. The fixture config uses a six-step cap and a zero-byte disk reserve. The first phase starts at zero; the second resumes step 3 with TK_JOB_START aged by 90,000 seconds; the third resumes step 4 for one further step. A 1.05-second delay after step 2 ensures that the native timer predicate fires. No smoke_steps path is used.

The copier runs as a separate child of the batch driver. It uses the emitted kit copier with a local target, an empty synthetic sessions map and a writer that saves four byte parts locally. Its m2 key maps to the production m100 object name in memory. No network, credential or session URL is used by that stand-in. Production upload authorization is unchanged.

`check_rehearsal.py` prints one line per requested path and its furthest observed stage. It returns nonzero until every path has evidence. A written script, a synthetic archive test, or a canary ADMIT does not establish that distributed training completed.
