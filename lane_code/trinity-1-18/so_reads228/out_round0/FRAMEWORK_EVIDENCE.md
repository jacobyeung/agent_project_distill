# Framework evidence

The tests use `/scratch/jjyeung/envs/p1cpu/bin/python -I -s -B` with CUDA hidden and eight CPU threads. The installed torch source is the supplied 2.11 CPU build. It supports the adapter's API usage; it does not establish RTX/H100 numerical equality or production environment equivalence. Network access was prohibited for this dispatch, so no online documentation was fetched.

| Behavior used | Installed source | Adapter use |
|---|---|---|
| Peak statistics reset to a new measurement interval. | [torch/cuda/memory.py:360](/scratch/jjyeung/envs/p1cpu/lib/python3.12/site-packages/torch/cuda/memory.py:360) | The observer resets at each item boundary. It does not free caches or change inference precision. |
| `max_memory_allocated` reports peak tensor allocation in bytes; `max_memory_reserved` reports peak caching-allocator reservation. | [memory.py:530](/scratch/jjyeung/envs/p1cpu/lib/python3.12/site-packages/torch/cuda/memory.py:530), [memory.py:566](/scratch/jjyeung/envs/p1cpu/lib/python3.12/site-packages/torch/cuda/memory.py:566) | Both values are written for each item, including a caught OOM. They include the resident model, not just incremental item allocations. |
| Allocator memory and `nvidia-smi` memory can differ because context and unused cached memory contribute to device usage. | [memory.py:513](/scratch/jjyeung/envs/p1cpu/lib/python3.12/site-packages/torch/cuda/memory.py:513) | The kit records both allocator peaks and one-second device telemetry. |
| CUDA synchronization waits for kernels in all streams on the selected device. | [torch/cuda/__init__.py:1152](/scratch/jjyeung/envs/p1cpu/lib/python3.12/site-packages/torch/cuda/__init__.py:1152) | The observer closes each item's measurement interval before reporting it. Synchronization can change timing; CPU tests cannot establish GPU parity. |
| CUDA OOM is the C++ `OutOfMemoryError` exposed by torch. | [cuda/__init__.py:433](/scratch/jjyeung/envs/p1cpu/lib/python3.12/site-packages/torch/cuda/__init__.py:433), [torch/_C/__init__.pyi:13008](/scratch/jjyeung/envs/p1cpu/lib/python3.12/site-packages/torch/_C/__init__.pyi:13008) | The worker catches this exception, records it, and exits 42 without retrying. A CUDA-OOM `RuntimeError` text fallback is also recognized. |
| CUDA availability and device-properties queries can initialize the driver/runtime. | [cuda/__init__.py:161](/scratch/jjyeung/envs/p1cpu/lib/python3.12/site-packages/torch/cuda/__init__.py:161), [cuda/__init__.py:1099](/scratch/jjyeung/envs/p1cpu/lib/python3.12/site-packages/torch/cuda/__init__.py:1099), [cuda/__init__.py:673](/scratch/jjyeung/envs/p1cpu/lib/python3.12/site-packages/torch/cuda/__init__.py:673) | Only the target worker calls these APIs, after the two idle readings. CPU tests inject a small CUDA API double. |
| `set_num_threads` controls CPU intra-op parallelism and should run before computation. | [torch/_torch_docs.py:9817](/scratch/jjyeung/envs/p1cpu/lib/python3.12/site-packages/torch/_torch_docs.py:9817) | CPU tests call `torch.set_num_threads(8)` before tensor work. The production worker keeps A4's four-thread environment. |
| SDPA can choose different CUDA implementations, and fused implementations can produce different outputs. | [torch/nn/functional.py:6030](/scratch/jjyeung/envs/p1cpu/lib/python3.12/site-packages/torch/nn/functional.py:6030), [functional.py:6048](/scratch/jjyeung/envs/p1cpu/lib/python3.12/site-packages/torch/nn/functional.py:6048) | Identical source and weight hashes do not prove H100/Ada answer equality. The first-50 comparison is mandatory. |

The relevant official references, not fetched in this network-free run, are [CUDA memory statistics](https://docs.pytorch.org/docs/2.11/generated/torch.cuda.memory.max_memory_allocated.html), [reserved memory](https://docs.pytorch.org/docs/2.11/generated/torch.cuda.memory.max_memory_reserved.html), [synchronize](https://docs.pytorch.org/docs/2.11/generated/torch.cuda.synchronize.html), and [SDPA](https://docs.pytorch.org/docs/2.11/generated/torch.nn.functional.scaled_dot_product_attention.html). The installed source above is the evidence used here.

The adapter records numerical settings and the model's installed attention functions without changing them. Those records describe the target run; the kit does not claim deterministic cross-device arithmetic. The CPU test suite checks the observer's call order and unchanged output objects, not CUDA allocator behavior.
