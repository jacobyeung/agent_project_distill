# Grounding rows, SPEC v3.12.2

Run the branch from the generator root with the existing CPU environment:

```sh
CUDA_VISIBLE_DEVICES='' PYTHONDONTWRITEBYTECODE=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 /scratch/jjyeung/envs/p1cpu/bin/python -B -m derivgen generate-ground --config CONFIG.json --output NEW_OUTPUT_DIRECTORY
```

The command produces diagnostic review rows from GT instance rasters and GT geometry. It calls a SHA-pinned copy of decode's `ground_lifting.py` and uses the same calculator. It does not fetch data or grant training admission. The `render` and `Session` APIs also accept an explicitly supplied backend for consumer integration.

The JSON config supplies pinned `{path, sha256}` entries for `backend`, `spec`, `tokenizer`, `benchmark_distribution`, `items`, and `scenes`; `reference_pins` pins the rkit modules and their imported program/tplib references. `rkit_root` is the import root. Set `diagnostic_only: true`, `per_type`, `miss_rate` (default 0.10), and `miss_seed`. Distance balancing uses `distance_bin_edges_m` (zero, increasing positive log-spaced edges, null for the tail) and positive integer `distance_bin_cap`. The pilot config is `ground_rows/work/pilot_input/CONFIG.json`. Use a new output directory for every build.

Each input JSONL row supplies `qid`, `type`, `question`, `options`, `scene`, the exact 32 `frame_indices`, `gt_answer`, and `gt_authority`. Roles are parsed from the original question; supplied roles must agree. A scene entry supplies a pinned GT NPZ, matching frame indices, and explicit exclusion status. The NPZ has native `depth`, `inst`, `K`, `c2w`, `valid`, `ids`, `labels`, `obb_centroid`, `obb_lengths`, `obb_axes`, and `frame_indices`, as rkit GTSource expects. Optional `K_frames[32,3,3]` supplies the exact per-frame intrinsics; the adapter runs the unchanged rkit lift with each frame's calibration. Native GT enters decode's frame-1 gravity world before the backend takes a median.

Every operand must resolve to one native instance and be visible in the recorded frames. A qualified name needs a verified instance binding. GT masks use native area >=0.002, nearest resize to 80x112, probability 1/0 and tau 0.5. Both producer and replayer call decode lifting with independent immutable-input caches and fresh point registries. Replay checks every serialized response and rejects unprinted point references.

The deterministic simulated-miss branch preserves the GT mask and substitutes the exact `NAME: not seen` response only after checking real visibility. A miss requires `direct_canonical`: exact `scene`, `frame_indices`, `question`, `options`, GT-matching `answer`, plus `body`, `form: vqa_canonical`, `source_sha256`, `source_path`, and `source_qid`. The join uses the original source options before permutation. The body is the existing question-matched VQA canonical derivation without its outer think/answer markers. Rows without an eligible continuation remain normal rows. Candidate selection excludes contradictory canonical wording and preserves admitted bodies byte for byte. The deterministic miss budget targets 10% of input ground rows and selects only eligible continuations; receipts report the realised share. The receipt records configured, selected and realized miss rates; the output retains continuation provenance. Genuinely invisible targets are dropped.

The pinned tokenizer is extended in CP1's token order with atomic `<ground` and `<gap`. It counts the complete suffix, including tool responses and answer, against 5,000 tokens. Rows record MDG gate token positions from the atomic ground opener through the closing call token. Tests compare these positions with decode's QueryStream. The consumer owns the complete multimodal token budget and embedding-row training/persistence.

`candidates.jsonl` retains rendered results; `gt_accepted.jsonl` retains answer-agreeing rows, including valid direct fallbacks. `balanced.jsonl` deduplicates by scene, exact frames, normalized question and operand names across types, then applies the existing benchmark aggregate (direction content with uniform letters, relative-distance uniform letters within each option count) and caps absolute-distance rows per log-spaced bin of the independent admitted-scene GT distribution. This numeric policy is explicitly not a benchmark-matched distribution. `not_seen.jsonl` contains direct fallback traces, never a not-seen answer. `dispositions.jsonl` records refusals and mismatches.

`RECEIPT.json` reports unfiltered v3.11/v3.12.2 agreement and agreement on the same accepted subset, content/letter/bin histograms, shortages, pins, suffix lengths and misses. Numeric agreement uses v3.11's <=5% relative gate with exact zero for zero GT; categorical agreement is exact. The renderer also rejects rounding-induced decision flips, short floor vectors, boundary cases and near ties on both raw and printed values.

The converted routing-scene manifest is present. Its GT paths require the ordinary host shell because this sandbox has a private /dev/shm. Production source membership/exclusions, VQA canonical joins and consumer token receipts still require admission. r7 rasters alone lack depth, K and poses. The production input contract is documented in the lane RESULT event and checked by `work/check_pending_inputs.py`.

Tests: `python -B test_v312_ground.py`. `V312_BACKEND` selects an explicit decode-module path. The lane also provides real GT/decode-adapter and native/real-row gate-position tests. No installation is required.

Normalize delivered CP2 rows with `python -B -m derivgen.ground_v312_input --input M_rows_selected.jsonl --input L_rows_selected.jsonl --scenes routing356_scenes.json --rkit-root RKIT --output NEW_DIRECTORY`. The default reads at most 100 source rows; `--full` must only be used after the cluster's heavy-IO approval. An optional `--direct-joins` JSONL supplies exact scene/frame/question/options/answer-matched canonical continuations. The normalizer checks GT/frame/scene pins, maps the two object-distance aliases, and records parser refusals. The builder permutes options deterministically from the row ID, rewrites choice lists, and renders answers against the new mapping. Operand gates refuse pairwise mask overlap, oriented-box overlap/containment, and a facing vector shorter than the larger projected full-box width.

Package reviewed outputs with `python -B -m derivgen pack-ground --build BUILD_DIRECTORY --output NEW_PACK_DIRECTORY`. Packed rows contain `target`, `question_type`, `trace_revision`, `form`, `tool_output_spans` and `loss_spans`; every forced response receives zero loss. The consumer must admit `spec-v3.12-ground-v1` / `3.12.2` and join RGB/production provenance before training. The package retains `training_admitted: false` for these diagnostic fixtures.

Run the complete source adapter, scene builder and global balancing with `python -B -m derivgen.ground_v312_production --help`; the lane wrapper is `ground_rows/out/run_production.sh`. It accepts a manifest and expected SHA256, GT root, repeated M/L `--input` paths and a new output directory. It checks every GT pin, source/code/reference/tokenizer pins and completed-output pins. Set all four thread variables (OMP, MKL, OPENBLAS, RAYON) to 1 and hide GPUs; workers are limited to 7 plus one coordinator. The wrapper supplies these settings. The RESULT event includes the exact approved host-shell command.

SIGINT/SIGTERM stops new scene submissions and finishes active scenes. Resume with the same inputs/output and `--resume --resume-reason user-stop`; after a cluster kill, obtain approval and use `approved-rerun`. The runner never retries automatically. A matching completed scene is reused; incomplete attempts remain on disk and get a new attempt directory. Global summaries are versioned. All outputs remain REVIEW-ONLY. The miss response is followed by the exact bridge `The tool did not find NAME, so I estimate from the frames.` After that bridge, the own-tool-output rule gives way to direct-source admission: preserve the question-matched derivation from the already-admitted VQA stream or its same canonical generator. Fixture admission is unproved, so these rows remain REVIEW-ONLY. Receipts report miss selection/rendering/missing-canonical counts per type.

The production CLI uses `--set-policy v2` and requires `--backend-sha256` for the reviewed lifting module. `set_before` and `set_after` report rows, unique questions and letter counts, with relative-distance option counts separated. `operand_rule_refusals` counts each triggered geometry rule independently; `miss_candidate_refusals` counts ineligible continuations by type and reason. All outputs remain REVIEW-ONLY.

Operand phrases must equal a matched GT label after case/whitespace normalization. A head-noun match alone does not admit qualifiers such as `wooden table`. The reviewed lifting pin remains v3.12.2; decode must reproduce the existing LF response layout, including calculator responses after a ground call.

Seen-ground headers use `NAME: frames FRAMES (best K)`; presence probability is private. The backend module must declare VERSION 3.12.2 and match the explicit SHA pin.
