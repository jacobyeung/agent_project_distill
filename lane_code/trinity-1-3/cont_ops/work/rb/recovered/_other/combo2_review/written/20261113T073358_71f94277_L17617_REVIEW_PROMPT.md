## What is under review

A spatial question-answering system measures distances and room sizes with programs that take object masks proposed by a segmenter (SAM 3) from text phrases. The base kit (`mask_recall_kit.tar.gz`) builds proposal caches for several variants and scores the programs on a development set. The fork (`kit_combo2.tar.gz`) adds two combined variants. One of them, `dense_aliases` (a dense text pass at a low score floor, then alias prompts on top, merged), is proposed as the frozen proposal setting for two question types, absolute distance and room size, because it scored +9.3 points [+4.2, +14.9] on absolute distance against the baseline on 150 development items. The setting will then be used to build proposal caches on benchmark scenes. The fork changes what the scored programs receive, so it needs one independent review before the freeze.

Read, in this order: `NOTE.md` (the builder's ten points, including what was not tested), `DIFF_base_30ebe415_to_combo2_0d2f2c14.patch` (118 lines, four files), then the functions the diff touches in the extracted fork under `test_run/kit_combo2` (extract the tars into a new folder of your own if you need the base), then `test_logs/`.

## Questions to answer, each with file and line evidence

1. **No answer leakage.** Where do the alias prompts come from? Confirm that every prompt the combos send to the segmenter is derived from the question's own phrase and a frozen alias table, never from ground-truth labels, ground-truth boxes or masks, or any per-item answer. Say how the alias table was built if the kit records it.
2. **Dense-cache reuse is sound.** Can a stale or mismatched dense cache (other frames, other thresholds, other manifest, other checkpoint) be reused without an error? Is the journal hash check sufficient, and what exactly does it bind?
3. **Base variants unchanged.** Does the retention cap of 100 in `contract()` or any other change alter the output of the base variants (baseline, dense, aliases, tiles)? It must not.
4. **Merge correctness.** After `merge_record` (IoU above 0.95 deduplicated, source scores kept, cap 100), can one object appear as two instances in a way that changes a measured distance, a count or the linker's choice? The builder reports counting falls by 8.3 points under this setting: is that explained by the merge, and is the restriction of the setting to absolute distance and room size therefore safe?
5. **Fair comparison.** Is the reported gain a like-for-like comparison: the same items, the same fusion rule, the same scoring code and the same frames for baseline and `dense_aliases`? Is anything in the fork tuned on the items it is scored on, beyond the stated choice among six variants?
6. **Determinism and resume.** Is the claimed byte-identical resume real for the combos, and what breaks it?
7. **Use on another manifest.** What must hold for the setting to mean the same thing on a benchmark-scene manifest (the kit holds only the development manifest today)? List the fields a new manifest must carry and any place the code assumes the development set.
