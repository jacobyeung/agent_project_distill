## Build: a self-contained package work/vla_heads/ (pure PyTorch; no dependency on StarVLA or on a simulator)
1. One interface for every head, so that the head type is a config value:
   - inputs: `lm_states [B,T,D]` from a chosen LM layer with `lm_mask [B,T]`; optional `cond_tokens [B,N,Dc]` (the model's own spatial outputs); `proprio [B,P]`; for training, `actions [B,K,A]` with a mask;
   - `loss(inputs, actions) -> {loss, parts}` and `predict(inputs) -> actions [B,K,A]`, both batch-first, dtype- and device-agnostic, bf16-safe.
2. Three heads:
   - (a) regression: K learnable action-query tokens appended to the LM input; an MLP maps their final states to the action chunk; L1 loss; one forward pass at inference (OpenVLA-OFT style).
   - (b) generative expert: a small transformer that cross-attends to `lm_states` and `cond_tokens` and denoises the action chunk. Implement both objectives behind one flag: conditional flow matching (linear path, velocity target, Euler sampler with a configurable step count) and DDPM/DDIM epsilon prediction (cosine schedule). Flags: depth, width, time-sampling distribution, sampler steps, and `detach_backbone` (no gradient from the expert into the LM, as in knowledge insulation).
   - (c) discrete tokens: per-dimension uniform bins (256 by default) mapped to reserved token ids that the LM writes autoregressively, with encode and decode and the cross-entropy targets a trainer needs; add a DCT-compressed variant (FAST style) if it fits without a new heavy dependency, else document the hook.
3. Conditioning switch `cond: none | g3t_tokens | spatial_readouts | both`: `none` is the pure backbone swap; `g3t_tokens` passes projected G3T tower tokens; `spatial_readouts` passes the model's own decoded quantities as tokens (camera pose per frame, depth summary or point depth, a grounded 3D target point or relative direction and distance). Define the tensor contract for each and a projector module; use synthetic tensors of the real shapes in tests (take the shapes from the tree's head and tower code).
4. Backbone adapter: `StubBackbone` (a tiny transformer) for tests, and `StudentAdapter`, which wraps the student model class of the tree: inserts action-query tokens or reserved action tokens, picks the tap layer, returns `lm_states` and `cond_tokens`, and sets which parameters train (frozen LM, LoRA if the tree has it, full fine-tune). The adapter must run on CPU against the tree's tiny native Qwen fixture.
5. Action utilities: per-dimension normalisation statistics (1st and 99th percentile to [-1, 1], saved as JSON, with a round-trip test), gripper handling, action chunking, temporal ensembling at evaluation, and proprioception encoding.
6. `examples/train_step.py` (one optimizer step per head on the tiny fixture, printing loss and gradient norm per module) and `examples/overfit.py`.
7. README.md: the interface, every config key with its default, how a trainer and a closed-loop evaluator call the package, and a table of parameter counts per head at Qwen3.5-9B's hidden size (computed from shapes, without loading weights).

## Tests (all on CPU; `python -m pytest work/vla_heads/tests -q` must pass; report the count and the runtime)
- shapes, masks, dtype and device handling for every head and every `cond` value;
- a toy overfit: each head fits 64 synthetic (state, action-chunk) pairs to a stated error within two minutes;
- a bimodal toy task that the generative expert fits and the regression head cannot (shows the reason to have it);
- token encode/decode round-trip error bound; normalisation round trip; chunking and ensembling;
- `detach_backbone` gives exactly zero gradient into the backbone, and the default gives a non-zero one;

- determinism under a fixed seed;
- the first batch through the tiny real-architecture student on CPU for every head and `cond` value (forward, loss, backward, one step).
