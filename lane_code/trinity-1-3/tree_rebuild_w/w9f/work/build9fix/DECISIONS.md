# Build 9fix decisions

- F1 baseline versus F5 extent refusal: measure the unchanged slices before enabling the extent receipt, then require the receipt for final intake and reader admission. This preserves separate evidence for each requirement.
- Extent variants: default to repaired rows; retain filtered source pins as an explicit input parameter. Never infer a verdict from the dataset name.
- Source isolation: rewrite executable path references in copied inputs; preserve the base tree as comparison evidence.
- Final restaging: use a fresh fixed kit folder for this build; retain existing kits as evidence.

- Audit evidence: an unknown result in the smaller audit and a full result in the full-unit audit are not conflicting decisive verdicts. Each family binds its named per-row audit; any half/full conflict refuses. Unknown rows in that family still refuse.

- Full-store division census: the VQA database has no metadata index; a census reads the full database. Options are an approved full scan or a bounded list/division check. Default: check every supplied removal key against the production division and keep the full-store proof blocked, because heavy-IO approval cannot be obtained during this run.

- F1 baseline count discrepancy: the pinned original units slice admits 1915 at intake, while the prompt requests 1895 for that family. Preserve the bytes and existing exclusions; do not tune admission to the requested count. BEFORE_EXTENT_GATE.json records the partial F1-only census. The final reader additionally applies the required F5 receipt.

- Archive size: options are to omit repeated input fixtures or compress the complete tar. Default: retain every member and use gzip compression with the requested `.tar` filename; DELIVERY.json states the format and both stored and member byte counts.

- Frozen package location: retain the unpacked qualification input at `proofs/package/frozen`, a fixed proof folder. Test scratch still uses `work/tmp` and the bounded test harness. This avoids treating the complete deliverable as temporary test data.
