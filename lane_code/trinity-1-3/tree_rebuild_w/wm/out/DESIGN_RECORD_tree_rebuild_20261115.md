## Build 1

**Question.** How can the next-leg tree admit honest traces and construct native trainer inputs before the real row and frame stores arrive?

**Answer.** Use one versioned grammar and manifest boundary, bind the accepted init at preparation, preserve native masked event encoding, and authenticate final row/target membership in the trainer. Build dense membership from content and source ordinals while retaining each row's clock. Missing frame material stops at an explicit host boundary.

**Reasons and evidence.** The recovered review failures concern raw logical reads, scene aliases, clocks, masked responses and missing exclusion receipts. The implemented paths and their exact source locations are in `BUILD1_REPORT.md`; retained tests, mutations and coverage are in `TEST_RESULTS.json`, `MUTATIONS.json`, `CPU_PATH_PROOF.json`, `FAMILY_ENCODER_PROOF.json` and `COVERAGE_CLASSIFIED.json`.

**Options rejected.** Flat direct targets containing responses would supervise external values. Path- or canonical-name-based dense identity would split identical content. Unknown scene overlap or missing upstream receipts would erase exclusions. An exact parent-run resume would hide changed code or mixture. A silent frame fixture would misrepresent a real-data proof. The implementation refuses each alternative.

**Defaults and risks.** The shared validator and real-row envelopes are unavailable, so the documented conservative syntax and versioned envelope are integration defaults. Metadata cannot prove visual relations. Native ground-event continuations rely on the admitted row lineage and printed response provenance; they do not claim a newly checked geometry backend. Full-store admission requires a separate frame host. The installed native video processor has a failure reproduced on the untouched base. These limits are disclosed in `BUILD1_REPORT.md`.

**Tests that settle the open points.** Reconcile the shared validator against the retained mutation corpus; publish the complete pinned family inventory; run `work/build1/REAL_ROW_PROOF.sh` on those inputs; then run native CPU admission with the real root map and export metadata on the frame host. Exercise full-store resource guards there before any GPU admission.

**Status.** The bounded build and synthetic CPU proofs are delivered. Real-row, frame-host and pretrained-model validation remain pending; no training or launch was performed. Exact counts, seal identities and source paths are in `BUILD1_REPORT.md`.

## Build 5

**Question.** Can the packaged source satisfy the CPU suite and changed-statement obligations while retaining conservative admission and making the missing frame-host work explicit?

**Answer.** CPU qualification complete; production remains blocked. The package binds the final sampler to admitted reader offsets, reserves retained archives, joins program frame metadata through the native pinned map reader, and requires every frame-host receipt before success. Evidence: `out/BUILD5_REPORT.md`, `work/build5/SUITE_COMPARISON.json`, `work/build5/CHANGED_COVERAGE.json`.

**Reasons.** A refusal after frame resolution changes reader offsets and must also change sampler indices. Native checkpoint files and their retained transport archives consume the same local disk. Missing frame metadata requires an authenticated map input. Runtime execution, archive staging, bank membership, vocabulary and native output visibility require actual host bytes. The implementation and CPU boundary tests are identified in `out/BUILD5_REPORT.md`; the real-byte obligations are in `out/FRAME_HOST_JOB.md`.

**Options rejected.** Keeping pre-refusal indices would select the wrong rows. Omitting retained archives would understate disk demand. Inventing frame metadata from answers would violate evidence provenance. Calling a synthetic host receipt a real-byte qualification would hide missing inputs. Weakening the repeat limit or full-store guard to fit a local test would alter admission. Keeping every scratch payload would violate the storage budget; completed owned scratch products instead become in-place hash receipts under the bounded harness.

**What might not work and how we notice.** The actual interpreter or archive layout may differ from the pinned plan; the runtime and staging steps refuse. Real map coverage or exclusions may reduce admitted populations; materialization records refusals and the sampler rechecks repeats. Real bank or vocabulary bytes may differ; the corresponding checklist step refuses. Native output paths, directory links or JSON may violate the visibility scanner; the output step refuses rather than granting an exception. The small transport round trip does not qualify a full trainer-state restore. A changed source, input or receipt invalidates its hash binding.

**Tests that would settle it.** Execute every numbered frame-host step against the pinned runtime, archives, map, bank files and export witness; inspect all receipts and the native-output scan. Separately qualify a durable full trainer-state restore before production authorization. No remote execution is authorized by this record.

**Status.** CPU qualification complete; production remains blocked. The source and package identities are in `out/TREE_SEAL.json` and `work/build5/DELIVERY.json`. Both kit authorizations remain closed. Exact suite counts, coverage classes and unexecuted checks are in `out/BUILD5_REPORT.md`.

The harness recorded refusals and compacted their products; measured peaks and test names are in `work/build5/REPORT_DETAILS.json`. This is not a claim that temporary usage never exceeded the cap.
