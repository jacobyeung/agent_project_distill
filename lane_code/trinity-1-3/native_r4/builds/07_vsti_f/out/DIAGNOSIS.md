7. **External termination or an interpreter/process failure.** SIGKILL, node loss, a fatal interpreter abort, or shutdown during finalization can bypass all Python cleanup. The supplied FAILED 1:0 and non-OOM observation favor an uncaught Python exception rather than a direct signal kill. A phase failure alone is insufficient. Nonzero worker exits and subprocess timeouts raise at `code/o.py:200`–`:201`; `:178` catches them and `:184` enters finalization. Errors while writing FAILURE/RESULT or parsing committed completion files (`:179`–`:183`) also enter that finally. A successful `return publish_read(...)` suppresses a pending exception. Finally, `code/o.py:223` calls main without passing its result to SystemExit. Therefore an ordinary handled worker failure, even with returncode=1 inside the return receipt, normally leaves the wrapper process at exit 0. Given the stage evidence, an escaping finalizer exception is the strongest explanation of the actual Slurm exit code. The child phase exception itself remains unknown because its log was lost.

Order of failure matters. The wrapper copies selected files and logs, then writes COMPLETE. The publisher checks token identity next, before member validation, compression, or either channel. For a digit-leading token, this identity check fails first unless assembly itself already failed. For an admitted token, the publisher creates its local spool/archive, then calls return_members to validate the complete member map. Within that sorted traversal, a file's suffix is checked before its size; compression starts only after the member map passes. A return that exceeds both expanded and archive limits therefore fails the expanded check first. The measured normal prepare outputs hit none of these caps.

V1f's guarantees have physical limits. It makes a fresh minimal publication attempt through the same publisher, channels, token and binding when full assembly/publication fails; an OSError during that attempt selects independent /dev/shm storage. The inherited timeouts, caps, mode, budgets and batch directives remain unchanged. Both unavailable channels, exhausted /tmp and /dev/shm, unreadable required evidence, protected journals alone exceeding a fixed cap, or fatal process loss cannot be overcome while retaining those constraints. A partial full publication can leave the pool token directory occupied; the same-token minimal attempt still has its independent GCS channel. No remote success or deadline duration was tested here.
