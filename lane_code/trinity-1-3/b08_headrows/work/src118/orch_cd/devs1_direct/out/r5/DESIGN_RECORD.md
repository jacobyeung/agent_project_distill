The dev adapter supplies a scoped summary wrapper for existing pass-3 and pass-4 cells. This is the smallest change because the reviewed kits already extract and score both dev-only MC types correctly per item; only their official summary rejects those type names. The wrapper preserves the original row checks, official rescorer, token-prefix checks where supplied by the kit, and CP1 budget authentication. It uses generic exact-option scoring for `relative_count` and `relative_size_object`, and an explicitly labeled item-weighted dev overall.

The merge-only entrypoint reconstructs and verifies the original code archive, verifies the request and payload pins, copies source journals unchanged, and changes only the unbound output path. It records the extension and input hashes separately from the generation binding. It never rewrites a reviewed kit, widens an official registry, or resumes generation under changed code. Pass-4 families share this merge path and retain their own-GT strata.

Full-journal CPU integration tests are required after any bind/merge/report change. Coverage includes every dev type, both kits and layouts, both CP1 budget arms, the two pass-4 families, summaries including the 4,096-token view, reports, and paired comparisons. Dry binds and isolated item-score tests do not establish that these downstream stages work.
