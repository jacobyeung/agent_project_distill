## Design: the model may change words, never facts
1. Fact source per target: the format A render (and the format E chain when its review passes; build for A first). Extract a fact set F with code before any call: every number with unit and the record it comes from; every entity mention (canonical object name and instance id); every relation (closer/farther, left/right/front/back, larger/smaller, before/after in appearance order, counts); every certainty marker present in the render; the answer string. Store F as JSON beside the target.
2. Gemini call 1 (rewrite): given the render and F, produce fluent second-person-free reasoning prose (no first person, no tool or frame references) that keeps every fact in F, adds nothing, and ends with the answer line verbatim. Temperature low. Prompt carries the six defect classes as forbidden moves with one example each drawn from the C-N dispositions (paraphrased, no qids).
3. Deterministic verification: extract F' from the output with the same extractor and require F' equals F (numbers exactly, entities and relations as sets, certainty markers preserved, answer byte-exact, no new numbers, entities or comparatives). Any difference rejects; one retry is allowed with the diff shown to the model; a second failure is a terminal rejection with the diff recorded.
4. Gemini call 2 (critic, independent prompt): given only the typed records and the candidate prose, list every claim not supported by the records or any dropped qualification; a non-empty list rejects. Record the critic output.
5. Apply the six mechanical filters from FILTER_ESTIMATES.json as final gates, plus the C-N lane's existing gates (numeric leak, voice, unknown entity, appearance overreach).
6. Output schema identical to the C-N lane's `diagnostic_set/candidate_index.jsonl` rows (so `finetune_freeform_v1_20260919` with `TRAIN_PARAMS_cn.env` consumes it unchanged), label `FREEFORM_CN_DIAGNOSTIC_PENDING_REVIEW`, plus per-row `fact_set.json`, `critic.json`, `gates.json` sidecars.
