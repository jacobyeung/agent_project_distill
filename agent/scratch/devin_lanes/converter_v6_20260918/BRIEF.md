## Design (orchestrator decisions 2026-09-18 19:00Z)
1. Stage A (fact sheet with line-id citations, identity table, scoped qualifications, corrections, calculations, failed checks) stays as in v5.2, with two additions: every calculation entry carries its operands' line ids and the precision the question requires (derive from the question text and options: integer counts, one decimal for meters, whole degrees, and so on; record the rule used); every observation entry carries a `conventions` field when a sign or direction convention is involved (for example "negative angle means the target is to the right"), cited to the line that states it.
2. Deterministic target rendering (no model call): the target text is produced by code from the validated sheet: a heading "Observations" with numbered items O1..On, each one sentence in plain visual language (object, where, size or relation, which frames), followed in the same item by its qualifications verbatim with their scope clause and by any correction as "initially X; corrected to Y because Z"; a heading "Calculations" with items C1..Cm giving operands (as O-ids), the operation in words, and the result rounded to the required precision (never the word "exactly" unless the result is an integer count); a heading "Reasoning" (see 3); a final line with the answer, byte-identical to the native bare answer. Object names come only from the identity table. A lint rejects any rendering containing process nouns (measurement, archived, execution, summary, verifier, plan, tool, mask, detector, pipeline, agent, model, prompt, step, call, code, array, variable, index, coordinates as triples) or a number that does not appear in the sheet at the rendered precision.
3. Stage B' (one model call): write the 3 to 6 sentence Reasoning paragraph from the rendered Observations and Calculations only. Every sentence must reference at least one O or C id in parentheses; the paragraph may not introduce numbers absent from the Calculations, object names absent from the identity table, or any process noun; a deterministic lint enforces this with one bounded repair. The paragraph must state any convention used (from the `conventions` fields) in plain words.
4. Stage C (semantic self-review, seven checks) reviews the sheet plus rendered target. Conservative adjudication: an advisory mechanical finding may be overruled only if stage C cites a line whose text literally contains the disputed element (the number, the identity name or instance id, the frame, the direction word); a deterministic check verifies the containment, otherwise the finding is upheld and triggers a sheet repair (one round) or rejection. Store every adjudication with the cited line text.
5. Pilot protocol: build the clean-pool job for the 8 oldest accepted qids in `ACCEPTED.json` whose question types cover at least four types (prefer two each of object_rel_direction_medium, object_rel_distance, object_abs_distance, obj_appearance_order) via the clean adapter strict snapshot; if the strict snapshot refuses, record why in `LANE/out/SNAPSHOT.md` and fall back to the 8 benchmark questions used in v5.2 (1600, 3919, 2544, 1506, 1555, 1569, 1575, 1582). Run stage A for all 8 (2 workers), then B' and C for validated sheets. Budget: at most 7 stage calls per question (3 A, B', B'-repair, C, C-repair), 56 in total, 32,768 output tokens per call, infrastructure retries as before. Write `LANE/out/STAGE_A_SUMMARY.md` and `LANE/out/STAGE_C_SUMMARY.md` as outcomes land.
