## Change
1. New schema `pool-harness-remote-drain-attestation-v1` produced by a new subcommand `attest_host_drained.py remote --host <predecessor> --evidence <snapshot.json> --pool <POOL> --package-commit <sha> [--write]`. Fields: `schema`; `host` (the covered predecessor); `verifier` {`host` (the machine that ran this command, from socket.gethostname), `pid`, `uid`, `argv`, `python`}; `verified_at` (UTC, when this command ran); `evidence` {`path`, `sha256`, `utc`, `command`, `stdout`, `rc`, `status`} copied from the snapshot; `workers` [{worker_id, pid, start_ticks, status: "absent_in_evidence"}] built from every worker_starts, heartbeats and claims record whose host equals `host`, exactly as `build` collects them; `record_counts`; `package_commit`; `assertions` {`evidence_status_pass`, `evidence_hostname_matches`, `evidence_no_matches`, `newest_record_before_evidence`}. The command refuses (nonzero, no file) when: the snapshot's `status` is not PASS or its `rc` is nonzero; the first stdout line is not the host name; the stdout does not show a no-match result for the pgrep patterns covering `collect.py` and the watchdog; any covered record's timestamp or file mtime is later than `evidence.utc`; or the record set is empty. `--write` publishes with exclusive create under `POOL/host_attestations/<host>__remote__<verified_at>.json`; without it, prints the JSON.
2. `require_drained` accepts a remote attestation for a foreign record only when the record's host equals `host`, the record's identity (worker_id, pid, start_ticks) is in `workers`, and the record's stamp is earlier than `evidence.utc` (not `verified_at`). The returned `drain_evidence` names the attestation path, its sha256, the evidence utc and `verifier.host`, so the launch receipt shows that verification was remote. The local `/proc` path, exit receipts, claims and orphan recovery stay byte-for-byte unchanged, and the existing local attestation path keeps working.
