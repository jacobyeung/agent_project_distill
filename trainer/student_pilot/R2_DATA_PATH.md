# Next-leg data entry

Run `python -m student_pilot.r2_intake --manifest FAMILY/MANIFEST.json --output intake.json` from an installed source tree. The command writes JSON to the output file and stdout, and prints per-type counts and reasons on stderr. Local slices default to the build brief's limit; the limit is enforced across manifests of the same family by the materializer.

The envelope is `r2-family-manifest-v1` with `family`, native `stream` (`vqa`, `routing`, `pose`, or `pointing`), population `count`, pinned JSONL or gzip `rows`, `row_bindings` mapping QID to the canonical row digest, pinned `scene_coverage`, `exclusions`, `prefiltered`, and `upstream_receipts`. A line contains a native row or `{row: NATIVE_ROW, target_record: NATIVE_POSE_TARGET}`. A native row may also carry `target_record`. This envelope is the documented integration default until the rows lane publishes its manifests; unknown envelopes refuse rather than guessing their meaning.

Scene coverage binds the row-file hash and the same exclusion pins, with `rows[QID] = {status: "known", names: [dataset-qualified names]}`. Names include the alias, canonical scene and physical room where known. Unknown coverage refuses. `r2_exclusions.SEALED` pins all supplied exclusion records by content, so callers can relocate records but cannot substitute their own lists. Upstream receipts bind those same pins and per-type `seen`, `admitted`, `refused`, and `reasons`. An upstream-filtered population must supply receipts. Qualification-only rooms are not an extra exclusion; the supplied evaluation and room-split exclusions remain active.

Direct rows declare `trace_contract = "next-leg-r2-v1"`, keep their native question, options, answer and target, and use explicit `Locate:`, `Relate:`, and `Step:` lines. The exact grammar is data in `trace_grammar.RULES`. Its `SOURCE_SHA256` hashes that data using canonical JSON; the tree seal binds executable code. Replace that module atomically with the rows lane's reviewed validator and compare both the data and refusal corpus. The current validator is deliberately conservative; it is a syntax and provenance gate, not proof that a visual relation is true.

Program rows retain the native `derivgen-row-v2` event structure. Only absolute distance and the camera types in `trace_grammar.PROGRAM_TYPES` enter routing. The adapter checks native rendering, adds answer delimiters to legacy camera answers, and rerenders response spans. Ground-form rows carrying this contract use the native ground-event renderer and declare `response_source` as ground truth or deployed, with source-row lineage. This admits a failed-call continuation without treating it as a legacy successful ground-truth record. Such a continuation must locate its fallback evidence and cannot call again. `carrier_c1_routing.encode` and `finish` own response-token masking. Room size enters VQA as direct text. A lineage-less room row is excluded by missing source-row and frame lineage, without an external QID list.

Rows lacking RGB pins require a pinned `frame_map`, keyed by QID. Each entry holds the native RGB manifest (`frames` with `source_index`, `fps`, `total_num_frames`, and optional `dense_source`). The adapter checks source ordinals before joining. A pending lineage record must match dataset, scene and indices. Pose `student_input.frame_prefix` prefixes relative frame filenames. A missing frame map is a metadata failure, not permission to fabricate pins.

Run `python -m student_pilot.r2_materialize --manifest FAMILY/MANIFEST.json --output NEW_DIRECTORY`. Repeat `--manifest` for distinct families. The API's `select_types` maps manifest paths to explicit type selections; select sealed routing's program types before combining it with re-rendered route-planning rows. An unfiltered ID collision refuses. `--metadata-only` records the frame-host boundary without opening RGB; `--no-dense` produces the control path. All other missing RGB or dense metadata produces a `needs the frame host` receipt and no store receipt.

The materializer writes native `rows(i,row,target)` SQLite stores, a pinned membership manifest and a combined receipt consumed by `carrier_c1_run.Rows`. Membership binds the final adapted row, its native target record and stream, and checks them on every read. Rows retain `r2_source_sha256` and `r2_envelope_sha256` for the original row and enclosing line. For wrapped lines, `row_bindings` hashes the complete wrapper, including the target record. Set `STUDENT_R2_LOCAL_NODE=1` on local proof nodes; full-store requests refuse. Trinity hostnames also refuse full stores. A separate admitted frame-host caller can set `STUDENT_R2_FRAME_HOST=1` and pass `--full`; that path is not executed on this node and requires the later job's resource guards.

All RGB paths pass through JSON `STUDENT_FRAME_ROOT_MAP`, using the longest path-component prefix. No unmapped logical shared-storage path is opened. The hash memo is process-local, bounded, and invalidated by device, inode, size or nanosecond mtime changes. Distinct files with identical expected content still require independent authentication; trusting a hash string alone would weaken refusal. Dense reconstruction inputs are selected by `dense_eval.nested_indices`; clips are keyed by ordered source ordinal and SHA-256 pairs. Each row retains its own clock and paths. The forward reconstructs from dense RGB before selecting language-model views, as implemented by the existing GF-1 path.

Next-leg configurations set `r2` to `{contract, init, mode: "warm_start", run_id, code_sha256, mixture_sha256, export_metadata}` and supply `r2_membership`. Membership without this binding refuses. `init` must equal `r2_contract.INIT`. `export_metadata` pins `metadata/EXPORT_ARTIFACT.json`; it must contain the accepted `artifact_sha256`. Optional parent fields must agree if supplied. The code identity is the native source seal's `tree_sha256`; the mixture identity is `digest({recipe, streams, route_table})`. Preparation verifies these bindings before any model load. The surviving parent configuration value is a prefix, never a fabricated complete hash. Existing legacy configurations remain usable for regression tests; build-two configurations must declare this contract.

Not checked here: real row envelopes, real RGB content and dense coverage, the Orchard export metadata's exact additional fields, pretrained tokenizer behavior, model weights, GPU memory or distributed execution. The external contract patches, configurations and launch remain outside this build.
